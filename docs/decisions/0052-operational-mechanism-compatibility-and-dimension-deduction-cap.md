# ADR-0052：运营机制兼容与维度累计扣分上限

- 状态：Accepted
- 日期：2026-08-21
- 关联：ADR-0033、ADR-0050、ADR-0051

## 背景

运营提供的灵感图机制需要在不复制平台能力的前提下接入特鹏标签中台。调用 A 新增了
标题、SEO 标题、风格和标签等生产字段，调用 B 采用无锚图五档维度评分，红线和值域也
可能随类目合同变化。平台必须在模型调用前发现 A/B/等级合同绑定错误，并允许合同正常
演进，而不是因为字段新增或规则数量增加就运行到中途才失败。

同时，维度内多条扣分规则的命中数量不应决定该维度是否被一次扣光。运营需要独立配置
“维度累计扣分上限”，与“维度最终分数上限”分开表达。

## 决策

1. 继续执行调用 A → 红线前置过滤 →（红线未命中时）调用 B → 服务端等级撮合与计分。
   红线命中直接短路 B；红线未形成足够证据时不得跳过 B。
2. `production_fields` 接收平台已支持的固定字段；对已观察到的 `\t` 前缀误写仅提供
   `title`/`tags` 两个窄别名兼容，未知字段仍按必填合同 fail-closed。
3. 维度新增可选字段 `dimension_deduction_cap`，取值为 0–100 的有限数值。命中规则的
   原始扣分为所有命中规则之和，实际扣分为
   `min(raw_rule_deduction, dimension_deduction_cap)`；未配置时按 100 处理，保持历史行为。
4. `dimension_score_cap` 继续表示最终维度得分上限，不与累计扣分上限复用。结果证据
   必须保留原始扣分、实际扣分、两个上限、是否触顶、维度得分及触顶原因。
5. 候选合同仍必须绑定具体 A/B Prompt 版本；绑定不一致在任何模型调用前拒绝。候选只
   能通过既有人工发布门启用，本 ADR 不改变发布权限和双人工门。

## 后果

- 运营可新增字段、红线业务值和维度规则而不依赖平台硬编码；合同错误能更早、更明确地
  反馈。
- 历史 deduction-v1、bonus-cap-v2 和 grade fallback 合同继续可读；只有显式设置新字段
  的合同才使用新的累计扣分上限。
- 机制配置页面需要同时展示“维度分数上限”和“维度累计扣分上限”，避免运营误把两者
  当成同一个概念。

## 验收与回退

- 合同与桥接专项测试覆盖旧合同、新字段、非法上限、A 字段别名以及多规则累计封顶。
- 后端全量测试除既有测试环境初始化失败外通过；前端 TypeScript/Vite 构建通过。
- 回退只撤销本 ADR 对应代码和编辑器改动；不删除或回写历史合同、评测结果、候选版本或
  NAS 素材。真实模型验证仍需在测试服恢复健康后，以 1 张素材单独执行。
