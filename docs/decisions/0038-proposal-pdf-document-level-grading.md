# ADR-0038：PDF 源文档级聚合、恢复与评分合同

- 状态：Accepted
- 日期：2026-08-07
- 取代：ADR-0035

## 背景

`proposal_text_pdf` 已能把源 PDF 逐页渲染并分批输入模型，但旧合并器把每批输出当成
一份独立完整结论。项目名称等普通元数据跨批不一致时，整份文档会直接进入人工复核；
某批连续两次输出无效时，剩余页面也不会继续扫描。这实际把“分页输入”误实现成了
“分页评分”，不能满足以源 PDF 为唯一归总对象的业务要求。

## 决策

1. `proposal_text_pdf` 的唯一评测对象是上传的源 PDF。逐页 JPEG/PNG 只作为调用 A/B
   的模型输入和证据载体，不创建页级样本、页级分数或页级等级。
2. 调用 A 的有效批次先聚合为一份文档级预检：红线证据去重取并集；普通标量采用首个
   非空值并把差异写入聚合审计；图像统计求和；内容完整性按
   `是 > 无法判断 > 否` 合并。
3. 审核类别按每个有效批次实际覆盖页数加权多数票确定。没有有效分类或最高票平局时，
   整份 PDF fail-closed 进入人工复核。
4. 每个原始页批仍最多校验两次。连续失败后确定性二分；默认 16 页批最多恢复四层
   （16→8→4→2→1）。任何单页仍不可恢复，整份 PDF 进入人工复核；所有供应商响应和
   失败页码保留审计。
5. 只有所有应扫描页面均被有效覆盖，或已发现真实文档级红线，调用 A 才算终止。
   红线淘汰不调用 B；普通元数据冲突不阻断 B。
6. 调用 B 接收源 PDF 的完整文本摘要、目录和引擎确定性选择的代表页，并被明确要求
   对整份源 PDF 评分。最终总分和 L1-L5 继续由服务端确定性合同生成。
7. 新任务冻结 `proposal-text-v2-document-aggregate-20260807` 及对应 v2 A/B Prompt。
   v1 历史结果只读保留，不回算、不改写。
8. 审核列表与详情页使用 PDF 文档级状态，不再套用图片维度完整性错误。系统不提供
   用户可见的逐页图片下载或导出能力。

## 后果

- 分批模型输出可以作为同一文档的互补证据，项目名称等局部提取差异不再误阻断评分。
- 分类收敛、页覆盖和恢复失败仍保持确定性、可审计和 fail-closed。
- 极端无效输出可能把 16 页批拆到单页，供应商调用数会上升；调用次数必须由预算与
  任务门禁约束，不能为了出等级跳过页面。
- PDF 的等级语义始终属于源文件，任何页图缓存均不得被下游解释为独立正式标签。

## 不可破坏约束

- 禁止对单页或页批生成可发布等级，再反向拼成 PDF 等级。
- 禁止用首批、代表页或部分可恢复页替代全页调用 A 覆盖。
- 禁止模型自行选择代表页、计算最终总分或决定 L1-L5。
- 真实红线命中必须立即作用于整份 PDF；普通字段冲突只能进入审计，不得伪装成红线。
- 未覆盖页、分类平票、单页不可恢复或合同无效时必须人工复核。
- 不新增逐页图片导出接口、页面或公开存储合同。
