# ADR-0035：PDF 方案文本分批页图输入通道

日期：2026-08-06
状态：已被 ADR-0038 取代

## 背景

proposal_text_pdf 初版沿用了通用 PDF 联系表，只向模型提供前 20 页。该做法无法保证
调用 A 全页扫描，也会让长图拼接降低单页细节清晰度。Owner 冻结了独立通道合同：
文本层优先、调用 A 分批全扫、调用 B 确定性代表页采样，并要求分阶段记录 token。

## 决策

- 禁止 proposal_text_pdf 使用长图或联系表；其它 PDF 类目的既有通道保持兼容。
- 原生文本层按全页抽取；只有无文本页使用 OCR，OCR 不可用时以页图补充。
- 调用 A 把每页独立渲染为长边 1024px 的 JPEG，每批 16 页，按页序串行调用。
- 每批输出独立严格校验，失败只重试 1 次；仍失败转人工复核，不改写响应。
- 任一批命中红线立即停止。红线取已扫描批次并集；信息字段先见优先，冲突转人工复核。
  图像统计是批次局部计数，作为唯一例外执行求和。
- 调用 B 由引擎最多选 16 页：封面固定保留，再按目录、文本关键词与调用 A 图像统计
  选择效果图、分析图和概念推导页，剩余名额均匀补齐。模型不得自选页面。
- 调用 B 使用 2 倍渲染 PNG，不主动降清晰度；输入同时包含目录、确定性文本层摘要和页图。
- 页批、实际扫描页、停止原因、代表页和 A/B token 分项写入前处理审计。

## 迁移

同一 spec 的已知旧配置只允许做一次受控升级：

- 流水线仅接受 document.page_contact_sheet 到 document.page_batches 的精确替换；
- v3 合同仅接受“缺少 pdf_input_channel 顶层块”的旧合同；
- 命中已知旧形态时 revision 加 1；任何其它差异 fail-closed，拒绝覆盖。

## 后果

- 长 PDF 的所有页面都进入调用 A，成本随页数按 16 页批次线性增长。
- 红线早停能减少后续批次成本，但完整通过的 PDF 会执行全部 A 批次和一次 B。
- 文本摘要有 30000 字符确定性上限；代表页图仍完整提供，审计会注明截断。
- 通用 PDF 联系表仍保留，避免改变 pdf_text 等既有类目行为。

## 不可破坏约束

1. 灵感图合同、提示词、评分与输入路径不得因本 ADR 改变。
2. proposal_aesthetic_score 必须在红线和等级映射前固化，规则不得回写。
3. 页数元数据小于 15 时不得调用模型；元数据不可读才回落调用 A。
4. 代表页必须由引擎确定性选择并留痕，禁止模型自选。
5. A/B 无效输出不得截断、补字段或静默容错。
6. 不得把凭据、全文模型响应或 PDF 正文写入报告。
