# ADR-0051：合同自有评分原语与自定义配置兼容

- 状态：Accepted
- 日期：2026-08-20
- 关联：ADR-0033、ADR-0034、ADR-0046、ADR-0050

## 背景

V3 候选合同已经允许运营自定义红线 reason、赛道调整和维度规则，但公共修正层仍把旧版本
的四个媒介键与 `A/B/record_only` 高分封顶 tier 当成平台固定枚举。运营只改合同内容就会在
候选保存前失败，即使评分目标已经改为硬伤逐条扣分且不设封顶。调用 A 适配器也仍会把合同
新增的硬伤/图像瑕疵值标为非法，造成合同声明、模型输出和执行器之间的不一致。

## 决策

1. `media_type_penalty.penalties` 的 key、baseline、fallback 和 alias 由冻结合同拥有；平台
   只校验非空引用、有限数值和 `<= 0` 的扣分范围。执行时优先使用合同直接 key，再使用合同
   alias，最后按合同 fallback/baseline 确定性回退；历史四键合同继续兼容内置别名。
2. `high_score_veto` 是可选公共原语。关闭或缺失时不要求旧 tiers；启用的 v2 veto 仍校验
   tier/action/cap/source 等可执行结构，但 tier 名称和 record-only 名称不再固定为 A、B、
   `record_only`。因此硬伤逐条扣分可以独立启用，不必伪造高分封顶配置。
3. `requires_any_hard_defect`、调用 A 的 `hard_defects` 和 `image_defects` 只校验非空业务
   字符串数组、重复性和证据结构，不再引用灵感图旧枚举。未知业务值只有在冻结合同规则精确
   引用时才产生评分效果。
4. 运营编辑器从当前合同读取媒介键，支持新增、删除和改名，并同步维护 baseline/fallback/
   alias 引用；平台 profile、信号源和维度输出结构仍是受控能力边界。

## 不可破坏约束

- 历史 revision、评测结果、原始模型响应、人工真值和冻结合同不回写、不重算。
- 业务值自由不等于任意执行代码：未知信号源、非法类型、非有限数值、坏引用和维度输出
  mismatch 继续 fail-closed。
- 合同声明的硬伤必须携带可定位证据；证据不足不得借兼容层直接淘汰或跳过调用 B。
- L1 最优、L5 最差以及旧 v1/v2 封顶语义保持不变。

## 验收与回退

- 新候选可保存三条自定义 reason、自定义媒介键、关闭且无旧 tiers 的 veto，以及每条硬伤扣
  10 分合同；聚合器按合同执行并保留审计证据。
- 旧合同合同/聚合/红线/适配器/3D-SU/纠偏回归全部通过，前端合同脚本和生产构建通过。
- 回退只撤销本 ADR 对应代码和前端编辑器改动；不删除或改写已冻结历史数据。部署回退使用
  部署前版本或快照。
