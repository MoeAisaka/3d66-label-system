# ADR-0032：生产消费字段与大批量基准回归合同

- 状态：Accepted
- 日期：2026-08-03

## 背景

实验台原先主要围绕分类、画质、媒介形态、维度分数和 L1-L5 结论组织结果，搜索推荐
实际消费的标题、SEO 标题、分类、风格、标签、点评等字段没有形成统一输出、纠偏和
发布合同。同时，基准回归页面只预览 1000 张，任务领取会反复扫描整个排队队列，
10000 张规模下会放大数据库读取和建单开销。

## 决策

1. 自由实验继续保留任意提示词和原始回答，不强制固定 JSON。只有显式选择“标准评分
   合同”的基准回归，才注入并严格校验生产消费字段。
2. 调用 A 在 `production_fields` 中返回 `title`、`seotitle`、`category`、`style`、
   `tags`、`cons`、`design`、初步 `score`、`reason`、`image_defects` 和 `trait`。
   使用独立对象是为了避免初步 `score`/过滤 `reason` 与服务端最终分数/评级理由混淆。
3. `image_quality.quality_severity` 和 `media_form.*` 继续保持现有结构，但标准合同会校验
   枚举、置信度和证据数组。字段缺失或越界时整条标准评测失败，不静默猜值。
4. 人工初审将这些字段纳入 `key_field` 真值，可与维度纠偏一起提交；只有关键字段变化
   时保持服务端既有最终分数和等级，不把调用 A 初步分误当最终结论。
5. 正式标签快照同时发布 `production_fields`、`image_quality`、`media_form` 和完整
   `key_fields`，人工真值覆盖模型值；历史发布版本仍不可变并可回滚。
6. 单个基准集继续以 10000 张为服务端硬上限。素材预览和回归结果使用每页 200 张的
   服务端分页，整包冻结由服务端处理；运行态轮询禁止反复传输或渲染 10000 条完整结果。
7. Worker 每类队列只分页寻找最老的可调度头部任务；调度器仍按原有五队列权重选择，
   不再为每次领取加载全部 queued 任务。基准 Run 先批量创建回归项，再批量创建任务，
   将逐条 flush 降为阶段性 flush。

## 后果

- 搜索推荐字段进入“模型输出、合同校验、人工纠偏、正式发布”的完整闭环。
- 10000 张容量不再依赖页面是否显示全部素材，大队列领取、建单、详情读取和运行态轮询的数据库与网络开销显著下降。
- 标准评分模式比自由实验更严格，旧提示词若未按合同返回字段会明确失败，需要先在小批
  金丝雀中验证提示词与模型兼容性。
- 本决策不自动提高模型并发上限。A/B 每张至少两次顺序调用，真实吞吐仍受供应商限流、
  图片上传带宽、模型延迟和当前 Worker 并发影响；提高并发必须先做真实 Key 金丝雀。

## 不可破坏约束

- 调用 A 的 `production_fields.score` 只能作为初步参考，不能覆盖服务端最终 `score` 或
  L1-L5。
- 自由实验不得因缺少生产字段被判为运行失败。
- `reason`、`trait`、画质严重度和媒介形态状态只能使用已声明枚举。
- 任何人工字段修正必须保留字段路径、模型值、人工值、原因和审核版本。
- 扩容不得通过一次加载或渲染 10000 张素材实现，也不得牺牲断路器、凭据和队列公平性。
