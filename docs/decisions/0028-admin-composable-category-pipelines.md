# ADR-0028：管理员可组合的模块化类目流水线

状态：Accepted

日期：2026-08-01

## 背景

实验台原先把空间图片、PDF 文本和材质图写成固定枚举。每新增一个业务类目，都要修改数据库约束、上传校验、Worker 分支和前端选项，既慢又容易让类目之间的 Prompt、维度、模型与自动优化状态串线。

## 决策

1. `EvaluationCategoryProfile` 升级为类目模板事实源，使用稳定 `category_key`，并保存版本化 `category-pipeline-v1` 合同。管理员可创建草稿、配置、启用和停用类目。
2. 类目合同由输入类型、允许 MIME/后缀、有序处理模块、提示词模式、附加指令、维度范围、节点开关和自动化配置组成。每个任务入队时冻结 `evaluation-category-profile-v2`，后续修改只影响新任务。
3. Worker 根据冻结模块执行，不再依赖 `category_key == pdf_text` 等名称判断。首期注册图片标准化、动图关键帧、PDF 文本提取、必要时 OCR、页图接触表、多模态总结和材质专项上下文。
4. 处理器采用服务端受控注册表。数据库只保存处理器 ID、顺序和经过白名单校验的参数；未知模块、错误输入输出顺序、非法参数、MIME 不匹配全部 fail-closed。
5. 管理员不得上传 Python/JavaScript 或任意命令作为处理器。出现全新底层媒体算法时，由工程发布一个受控模块；发布后管理员可以在任意类目中自由组合，无需再次改业务代码。
6. 旧三类目由迁移 v40 回填等价流水线。SQLite 重建类目表以移除固定三值 `CHECK`，并在迁移后执行 `PRAGMA foreign_key_check`。
7. 指标和模型节点同样来自服务端受控目录。管理员通过复选框选择现役八维指标的重点解释范围，不接受任意指标字符串；模型节点固定为主评测、文档多模态总结、提示词优化、模型横评和诊断，主评测节点不可关闭。

## 后果

- 普通图片、动图、PDF 及其业务变体可以通过管理界面新增队列类型。
- 类目 Prompt、处理链、模型节点和指标关注范围保持隔离；停用类目只阻止新任务，不破坏历史结果。
- 当前 L1-L5 权威评分仍要求至少启用一组维度；“按需指标”用于冻结类目重点解释范围。完全无维度的直出等级需要单独的评分合同和回归门禁，不能伪装成现有八维评分。
- 历史 `evaluation-category-profile-v1` 任务继续由 Worker 兼容执行，新任务统一冻结 v2。

## 不可破坏约束

1. 已入队任务的类目合同不可随模板更新漂移。
2. 未知处理器、非法顺序和越界参数必须拒绝，不能静默跳过。
3. 草稿和停用类目不得接收上传或新任务。
4. API 与 Worker 不得重新引入基于业务类目名称的执行分支。
5. 类目删除不得级联破坏素材、黄金集、回归、反馈或审计；首期只提供停用。
6. 类目模板只能组合已发布的指标和节点能力；新增底层指标、评分算法或执行节点仍需通过维度管理、校准和工程发布门禁。
