# ADR-0039：统一等级语义与类目级启停档位

## 状态

Accepted，2026-08-10。

## 背景

现役 v3 评测已采用 L1 最优、L5 最差，但仓库仍保留旧的 `v1-l5-best` 语义标记。不同类目还需要不同颗粒度，例如关闭 L5 后只使用 L1—L4。关闭档位不能重新引入方向分叉，也不能让严重问题绕过硬过滤。

## 决策

1. 所有现役类目统一采用 `L1=最优`，L 序号越大质量越差；生产写入不再保留 `v1-l5-best` 分支。
2. 等级机器标识仍限定为 `L1`—`L5`，不允许类目反转方向或新增 `L6`。
3. 类目可在冻结的 v3 合同中配置 `level_scale`：
   - 启用或关闭某档，例如关闭 L5 后只产出 L1—L4；
   - 调整启用档的 `min_score`；
   - 配置面向用户的 `display_name`。
4. 最差的启用档必须以 `min_score=0` 兜底。关闭 L5 时，L4 必须成为兜底档，任何分数都不得产出 L5。
5. 红线策略的 `hit_level` 必须是当前类目启用档；关闭 L5 的类目必须显式将红线等级改为 L4。红线命中仍保留 `hard_reject=true` 和原因证据，展示档位不承担业务屏蔽的全部语义。
6. 未配置 `level_scale` 的旧合同继续使用默认五档；旧 `level_thresholds` 可读兼容，但不能与 `level_scale` 同时存在。
7. 本次不重建数据库 CHECK：物理字段本来就允许 L1—L5，关闭档位是类目合同的子集约束，由合同校验和聚合器共同 fail-closed。

## 合同示例

```json
{
  "level_scale": {
    "version": "category-level-scale-v1",
    "levels": [
      {"level": "L1", "enabled": true, "min_score": 80, "display_name": "优选"},
      {"level": "L2", "enabled": true, "min_score": 60, "display_name": "良好"},
      {"level": "L3", "enabled": true, "min_score": 40, "display_name": "常规"},
      {"level": "L4", "enabled": true, "min_score": 0, "display_name": "过滤"},
      {"level": "L5", "enabled": false, "display_name": "停用"}
    ]
  }
}
```

## 理由

关闭某个等级是类目颗粒度变化，不是语义方向变化。统一方向可避免同一个 L5 在不同类目分别表示“最好”和“最差”；启停档位又能覆盖类目只需要 L1—L4 或三档的实际需求。

相对质量等级与搜索推荐处置必须分层。即使关闭 L5，严重问题仍可通过门禁状态、`hard_reject` 和原因码进入硬过滤，不应依赖“是否存在 L5”决定是否屏蔽。

## 兼容与回退

- 早期无语义标记的历史评测行不自动翻值，只作为历史证据保留。
- 默认五档合同不变，旧结果可继续回放。
- 回退时移除类目合同中的 `level_scale` 即恢复默认五档；不需要数据库逆向迁移。
- 配置非法、阈值逆序、兜底缺失、红线命中停用档时拒绝保存或拒绝聚合，不降级猜测。

## 不可破坏约束

- L1 永远最优，L 序号越大质量越差。
- 停用等级不得出现在正式聚合结果中。
- 硬过滤状态与相对质量档位分离；关闭 L5 不得取消红线证据。
- 同一冻结合同中不得同时配置 `level_scale` 与旧 `level_thresholds`。

## 验收

- 默认合同继续产出 L1—L5。
- 关闭 L5 的合同在 0—100 全分域内只产出 L1—L4。
- 红线命中停用等级时合同校验失败；改为 L4 后硬过滤证据完整。
- 专项与全量后端测试、`git diff --check` 全绿。
