# ADR-0050：合同自有红线业务值与调用 A 后前置过滤

## 状态

Accepted（2026-08-20）

## 背景

V3 红线规则允许运营自由增删，但 `production_fields.reason` 与
`redline_policy.rules[*].match_any` 曾同时受到代码内全局枚举限制。运营在合同中新增
透明棋盘格、手绘草稿等业务判断时，前端可以填写，候选却会被服务端拒绝；即使提示词和
合同已同步，新值仍需研发改代码，违背 ADR-0033 的按类目可配置目标与 ADR-0049 的冻结
合同原则。

同时，红线虽然在确定性聚合器中具有终止语义，worker 过去借用“是否使用规则扣分 B”探针
绕过调用 B。该探针只看原始 `reason`，没有独立验证命中证据，导致红线前置过滤的路由
条件与最终权威评分条件不一致。

## 决策

1. `redline_policy.rules[*].match_any` 的业务字符串由每个版本合同自行声明。平台只校验
   非空字符串、规则结构、唯一标识、受支持信号源与确定性动作，不再校验全局 reason
   枚举成员关系。
2. 调用 A 的 `reason` 保存任意非空业务字符串；只有冻结合同中的精确匹配规则能够触发
   红线动作。未知值会被保留用于审计，但不会自行产生评分效果。
3. 新运行的纠偏合同从冻结 V3 红线规则派生 `call_a.reason` 选项；历史运行继续读取自己
   已冻结的纠偏合同和 V3 合同，不从现役配置补齐。人工纠偏界面的 reason 选项同样读取
   结果内冻结的 V3 合同，不再展示平台固定六项。
4. worker 在调用 A 完成后计算一次 evidence-aware 红线前置判断。声明权威前检合同的链路
   只有在规则值命中、对应布尔信号为 true 且证据数组非空时才确认命中；确认命中立即
   输出 `L5 + hard_reject`，不发起调用 B。
5. 原始 reason 命中但证据不足时不淘汰，正常进入调用 B。最终评分使用分离的评分输入与
   合同副本：移除只属于未确认规则的 reason，并仅在评分副本中禁用未确认规则，避免后段
   重新判成 L5；原始调用 A 输出、冻结合同、证据错误和前置判断完整保留。
6. 不声明权威前检证据合同的历史 V3 配置保留原有确定性 reason 匹配行为。既有灵感图规则
   可使用兼容证据键映射；新规则默认以自身稳定 rule key 对应调用 A 布尔与证据键。
7. 灵感图回归附加给调用 A 的权威前检说明，从该运行冻结的红线规则动态生成布尔键、证据键
   与 reason 值；平台不再在冻结 Prompt 之外追加旧六项白名单。

## 后果

- 运营新增或改名 reason 业务值时，不再需要同步修改平台枚举代码。
- 红线样本节省一次无意义的美感模型调用，非红线和证据不足样本仍获得正常 B 评测。
- 合同值自由不等于执行能力自由：浏览器仍不能提交可执行代码，未实现的信号源、字段类型、
  哈希漂移和无效结构继续失败关闭。
- 前置判断成为正式审计数据，需要与原始 A 输出和最终评分一同保留。

## 不可破坏约束

- 历史评测、原始响应、人工真值和冻结合同不得改写。
- 只有冻结合同内的精确规则能够影响 L 等级；任意模型自由文本不得直接触发淘汰。
- 证据不足的红线不得短路 B，也不得在后段重新生效。
- 已确认红线不得调用 B；该约束必须由 worker 端到端测试验证，而不只测试纯聚合函数。
- 同次命中多条规则时，最终 `hit_rules` 只保留有证据的规则；无证据规则只留在原始 A 和
  `redline_prefilter` 审计中。
- L1 最优、L5 最差的版本语义保持不变。

## 验收与回退

- 自定义 reason 合同能通过校验、冻结到纠偏元数据并确定性命中。
- 有证据命中只产生一次模型调用并输出 L5；同一 reason 缺证据时产生 A、B 两次调用且结果
  不为 L5。
- 旧合同、旧六项 reason 与既有红线/美感测试全部通过。
- 回退仅撤销本 ADR 对应代码；不改写已经冻结的历史合同或结果。
