# ADR-0019：审核身份由服务端登录会话派生

- 状态：Accepted
- 日期：2026-07-30

## 背景

人工审核、初审组投票、主审裁决、配对回归审批和模型迁移复核的旧 API
都接收客户端提交的审核姓名。客户端可修改这些字段，因而不能把它们作为
真实审核员的审计身份。系统已经有 Cookie 会话：服务端保存会话 token 的
SHA-256 哈希，并通过 `session_tokens.user_id` 关联登录账号。

## 决策

- 所有审核写入统一使用 `current_user` 从有效登录会话解析出的
  `User.username` 作为审核员身份。
- 旧请求中的 `reviewer_name` 和 `lead_reviewer_name` 保持可解析，以兼容
  既有客户端，但不参与身份查重、落库、审批幂等或审计署名。
- 初审组读取接口继续解析旧 `reviewer_name` 查询参数，但“我的票”只按当前
  登录账号选择，不能通过查询参数读取其他审核员的盲审票。
- 前端从 `/api/auth/me` 取得当前账号，在审核入口只读展示，不再保存或允许
  编辑独立的审核姓名。

## 后果

- 修改请求体或查询参数不能伪造真实审核员身份。
- 历史数据和旧 API 形状保持可读、可解析；既有审计字段继续保存字符串值。
- 多人初审必须由不同登录账号分别提交。共用同一账号的操作在审计上仍属于
  同一身份，也不能绕过同一审核员只能投票一次的限制。

## 不可破坏约束

- 不改变 ReviewPanel 收齐全部冻结席位后再按 B 口径结算的语义。
- 不改变六个一级工作域、角色权限范围或历史审核状态机兼容边界。
- 不改变 ADR-0016 的默认关闭、dry-run、零预算和横评 test 安全默认值。
- 不新增运行时依赖。
