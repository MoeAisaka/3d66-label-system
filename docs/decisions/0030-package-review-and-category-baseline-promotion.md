# ADR-0030：评测包二审、显式发布与类目基线原子提升

- 状态：Accepted
- 日期：2026-08-02

## 背景

实验台的最终产物不是孤立的 Prompt，而是冻结新版 Prompt、维度指标、黄金集、
模型合同与配对回归证据的评测包。自动优化可以生成候选，但一线审核员必须先看到
完整证据并完成二审；只有明确的发布动作才能改变类目后续任务使用的执行基线。

过去的通用 `StrategyBundle` 工厂可能在创建或复用 Bundle 时隐式写入类目基线。
这会产生“第一个匹配调用抢占基线”的副作用，也无法区分候选生成、二审通过和正式
发布。全局归档同阶段已发布 Prompt 还会影响其他类目继续使用自己的现役版本。

## 决策

1. `get_or_create_bundle` 只负责创建或复用不可变 Bundle，不得修改类目配置。
2. 自动优化启动时按完整类目合同解析基线：A/B Prompt、模型非密快照、Rubric 和
   维度合同必须全部一致，且只能有一个候选。零匹配、多匹配或合同漂移均阻塞并返回
   稳定原因，不领取案例。
3. 自动优化 Run 冻结类目、Profile 版本和基线 Bundle；候选生成及配对回归前再次
   校验，防止运行期间配置漂移或跨类目串线。
4. 评测包二审的 `approved` 只表示证据获准进入发布步骤，不改变 Prompt 或类目基线。
5. `publish` 是唯一的基线提升操作。它在一个事务内将评测包冻结的 A/B Prompt、
   模型配置、Rubric、维度合同与候选 Bundle 写入所属类目，并增加自动化修订号。
   任一合同无法唯一解析或不一致时整体失败。
6. Prompt 的 `published` 状态允许多个类目保留不同现役版本。发布新包时只记录该类目
   上一个 Prompt 作为回滚点，不全局归档其他类目仍在使用的同阶段 Prompt。
7. 活动类目只能绑定已发布 Prompt。普通审核员不能填写 Bundle ID；管理员可在高级
   设置中显式绑定，但仍必须通过完整合同校验。
8. Worker 就绪状态持久化心跳、最近检查、活跃原因与阻塞原因。有效 processing lease
   视为活跃，避免长模型调用被误报为 Worker 离线。多类目调度保存最近服务时间，按
   确定性轮转避免可运行类目饥饿。

## 后果

- 一线审核员的默认路径收敛为导入素材、开始评测、处理纠偏、查看完整评测包、二审
  并显式发布；模型协议、预算、执行器和 Bundle 身份留在管理员高级设置。
- 二审与发布成为两个可审计、可重试且语义不同的状态，自动流程无法绕过人工发布。
- 多类目可以共享部分 Prompt 或模型资产，但执行基线、黄金集、维度与回归证据保持
  类目隔离。
- 升级前没有显式基线的类目仅在完整合同唯一匹配时自动冻结旧基线；歧义数据需要
  管理员处理，不做猜测。

## 不可破坏约束

- 通用 Bundle 创建、候选生成和二审批准不得修改类目现役基线。
- 发布必须校验评测包状态、类目身份和完整冻结合同，并在同一事务内完成。
- 不得全局归档仍被其他类目引用的已发布 Prompt。
- 不得把过期心跳单独等同于 Worker 离线；未过期处理租约必须纳入活跃判断。
- 不得让持续有任务的类目无限饿死其他同时可运行类目。
