# ADR-0029：统一标签生产与消费合同

- 状态：Accepted
- 日期：2026-08-01

## 背景

标签实验台将成为内容平台的统一标签生产与治理入口：上游持续产生内容增量，实验台完成模型候选、人工纠偏、回归与二审，下游搜索、推荐和前端消费正式标签。原有系统已有评测、人工真值和优化队列，但没有可供跨系统消费的发布事实、版本或变更流。

真实下游尚未接入期间，操作员需要把正式标签交付给临时分析或业务方。该能力不能绕过发布层，也不能让候选表、模型原始响应或密钥进入文件。

## 决策

1. 标签分为三个不可混淆的层次：
   - `candidate`：模型结果与未结束的人审过程，只在实验台内部使用。
   - `confirmed`：完成 `ReviewPanel` 的人工真值，模型后续运行不得覆盖。
   - `published`：经过人工二审发布后，由 `PublishedLabel` 保存的只读消费事实。
2. 上游以 `content-ingress-v1` 接收 `content.created`、`content.updated`、`content.deleted`。事件按 `event_id` 幂等，载荷漂移返回冲突；乱序事件记录为 `stale`，不回写较新的内容投影。
3. 上游事件没有对应本地素材时进入 `awaiting_material`，不伪造评测任务或下载外部文件。后续连接器或受控上传将素材绑定后才能入队。
4. 发布由 `LabelRelease` 记录请求和人工审批；只有完成初审且结论为 `approved`/`corrected` 的结果可发布。发布冻结标签、人工真值和策略溯源。
5. 每次发布或回滚均生成新的 `PublishedLabel.version`。回滚是以历史标签创建新发布版本，绝不修改或删除已发布历史。
6. 下游只通过 `/api/consumer/v1/labels/{content_key}` 和 `/api/consumer/v1/changes` 读取 `PublishedLabel` 与 `LabelOutboxEvent`。上游写入使用 `CONTENT_INGRESS_TOKEN`，下游读取使用独立的 `LABEL_CONSUMER_TOKEN`；二者不接受浏览器会话，消费者以顺序 cursor 拉取并自行确认 checkpoint。
7. 发布标签与 Outbox 在同一数据库事务中写入。当前不调用外部 webhook、不直连下游数据库，跨系统以可重放、可对账的最终一致性实现。
8. 手动导出与自动消费共用 `PublishedLabel` 事实源。操作员可导出当前生效标签或全部历史版本，格式为 XLSX、CSV 或 JSON；导出受 `releases:read` 权限、类目/发布时间筛选、单次 10,000 条上限和只追加审计约束。
9. CSV 对可能被电子表格识别为公式的文本做中和；XLSX 使用字符串单元格保存标识符和 JSON 字段。文件不包含候选标签、模型原始响应、人工过程明细或凭据。

## 后果

- 下游无法读取模型候选、评测原始响应或人工过程数据，避免把未确认结果直接展示给用户。
- 上游和下游接口在外部平台尚未就绪时可通过本地合同、幂等事件和对账 API 验收；不宣称已完成真实平台联通。
- 发布需要人工二审，自动优化只能生成候选与回归证据，不能绕过发布门禁。
- 当前 SQLite 是实验台事实源。生产规模或并发需求上升时可迁移到 PostgreSQL，但 API、版本和 Outbox 合同保持不变。

## 不可破坏约束

- 不允许前端、搜索或推荐直接查询候选、人工审核或评测结果表。
- 不允许模型自动覆盖人工真值或自动发布。
- 不允许通过删除历史标签实现回滚。
- 不允许在 API 请求事务里同步写下游业务数据库。
