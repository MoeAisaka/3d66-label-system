# ADR-0041：TPENG 标签实验台（LabelLab）标签机制与模型管理执行合同 v1

## 状态

已接受；v1 控制面已实现（2026-08-11）

关联：ADR-0042（TPENG 标签实验台统一产品载体定位）、ADR-0043（Canonical 事实与语义投影边界）

## 背景

TPENG 标签实验台（LabelLab）是标签体系重构的统一产品载体，也是标签/内容中台重构的
通用底座，负责待评素材导入、类目路由、类目评测与标签标注、人工纠偏、机制迭代、结果发布
和下游消费。它不再与“标签体系重构”作为两条独立项目线规划，也不是仅承担评测的单点工具。
人工纠偏会产生可用于自动分析的样本，AI 只能生成候选评测机制与回归证据，最终由人工决定
是否启用。不同类目的评测机制差异很大，同时需要用新版机制对存量标签和美感分进行可追溯重跑。

现有仓库已经具备 `CategoryEvaluationV3Config`、`EvaluationPackage`、`BaselineRegressionRun`、`ReviewPanel` 以及 `LabelRelease/PublishedLabel/Outbox` 等基础能力，但模型配置仍以主模型单例 + 调优模型单例为主，且两个发布轴尚未以统一合同表达。

## 决策

### 0. 统一产品载体与类目扩展边界

本合同内的模型注册中心、类目评测机制、人工纠偏、AI 迭代、双发布轴、存量重跑和下游发布
均属于 TPENG 标签实验台统一底座。业务类目只能扩展自己的评测合同、提示词、维度、规则和
回归门槛，不复制平台通用能力。该定位对齐不改变本合同的范围、非目标、权限、回退或验收。

### 1. 两条独立发布轴

系统维护两个互不隐式触发的发布轴：

- **机制发布轴**：决定新评测任务解析到的机制版本。
- **标签事实发布轴**：决定新增结果或存量重跑结果是否成为下游正式标签事实。

启用新机制不会自动触发存量重跑，也不会覆盖历史标签。下游只读取正式发布事实，不读取候选、原始模型响应或人工过程数据。

上层 Canonical 事实、资产语义投影和向量责任边界遵循 ADR-0043；该约束不扩大本 v1 合同。

### 2. 机制合同

机制采用“预设模板 + 高级自定义 + 组合编排”。合同必须显式声明：类目、版本、输入类型、执行器、A/B 或单提示词模式、维度与权重、红线、扣分、等级映射、证据、置信度、人工分流、黄金集、回归门槛、发布和回退策略。

每次任务和回归冻结机制合同、模型快照、提示词、规则、执行参数和素材范围。缺少执行器、合同损坏或回归证据不足时 fail-closed，不能启用。

### 3. 模型管理中心

模型采用列表型注册：

- `main`：主模型，可配置多个，按类目、节点和任务类型绑定；
- `tuning`：调优模型，可配置多个，仅供 AI 自动迭代机制使用；
- `benchmark`：横评候选，可复用主模型配置但必须显式启用。

每个注册项保存名称、供应商、协议、端点、模型 ID、能力标签、Token 上限、价格、并发/速率/预算限制、thinking 开关、层级、启停状态和安全凭据引用。API Key 只保存安全引用，不在响应中返回明文。

协议白名单为：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、受控 OpenAI-compatible JSON（覆盖豆包 Ark）。新增协议只能通过适配器注册，不允许用户注入任意 Header 或代码。

任务、回归和候选包冻结非密模型快照与凭据引用；停用模型不影响历史记录。

### 4. 存量重跑

存量重跑必须冻结素材范围、旧/新机制、模型、提示词、规则和执行参数，生成新的重跑版本与结果。重跑结果只有在标签事实发布轴显式批准后，才可替代下游读取的正式事实；历史事实保留，可回滚到前一发布版本。

## 非目标

- 不访问正式数据库、真实模型批量调用或真实密钥；
- 不自动发布 AI 候选；
- 不在本阶段实现所有类目的专用执行器；`inspiration_image` 是第一套完整参考类目，其余类目先保留合同/预设/绑定能力；
- 不因机制启用自动触发存量重跑。

## 验收

- 后端新增/修改行为均有先失败后通过的确定性测试；
- 前端模型管理页为列表 + 新建/编辑抽屉，能区分主模型与调优模型；
- 协议、Token、价格、并发/预算、thinking、层级和启停状态可读写并安全脱敏；
- 机制启用、标签事实发布、回退和存量重跑门禁 fail-closed；
- 后端测试、前端正式构建、浏览器关键路径、`git diff --check` 全部通过；
- `PROJECT_STATUS.md` 和本 ADR 的实现状态同步更新。

## 实现结果（2026-08-11）

- 增量迁移 61 新增统一模型注册表；旧主模型与调优模型表继续作为运行兼容层。兼容投影
  仅在旧表具备完整所需字段时执行，且显式写入创建/更新时间，避免最小历史表误投影及
  ORM 预建目标表缺少数据库时间默认值的问题。
- `/api/model-registry` 提供列表、新建、编辑、启停、连接参数检查和绑定查询；响应不输出
  密文或安全存储引用。前端使用列表 + 右侧抽屉管理 `main/tuning/benchmark`。
- 增量迁移 62 新增 `MechanismRelease` 与 `StockRerun`。人工发布评测包时事务性创建机制
  revision，且不会隐式创建重跑、`LabelRelease` 或 `PublishedLabel`。
- 存量重跑创建时冻结素材清单、机制 manifest、模型、提示词、规则和执行参数，并验证类目、
  manifest 哈希、评测执行器与回归 release gate。当前执行快照固定为 `dry_run_only`，明确
  `publishes_labels_automatically=false`。
- 标签事实继续只通过既有 `LabelRelease/PublishedLabel/Outbox` 显式发布和回滚；机制发布
  与标签事实发布拥有独立 revision 和审计记录。
- 验证证据：后端全量 `1203 passed, 4 skipped`；迁移修复定向套件 `50 passed`；前端合同、
  production build、lightbox 浏览器契约通过；模型注册中心桌面与 390×844 浏览器验收通过，
  控制台 error 为 0。

### 已知边界

- 本版本实现的是存量重跑控制面和快照门禁，未接真实批量 Worker、重跑结果差异工作台或
  批量标签发布申请。
- 机制轴尚未提供人工回滚 API；后续必须采用追加 revision 回滚，不能改写历史 release。
- 未部署生产环境，未调用真实模型，未迁移或保存真实凭据。

## 回退

所有新表/字段和 API 均采用增量迁移；旧的 `/api/model-config`、`/api/optimizer-config` 保留兼容。若新注册中心或发布门禁出现问题，可停用新入口并继续使用现有快照链，不删除历史数据。
