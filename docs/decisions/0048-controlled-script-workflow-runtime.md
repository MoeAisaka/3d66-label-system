# ADR-0048：受控脚本注册与工作流运行时底座

- 状态：Accepted
- 日期：2026-08-15
- 决策范围：TPENG 标签实验台通用底座，本地 `dry_run` 批次

## 背景

标签实验台已经是标签体系重构的统一产品载体。为了让增量接入、评测、打标、纠偏、发布、投影、对账和 Badcase 回流能够按类目模块化组合，平台需要一个可审计、可恢复、可复用的脚本注册与工作流运行时，而不能继续把每个类目的自动化链路写成独立脚本或第二套调度系统。

本批只建设本地运行时底座，用确定性夹具证明版本冻结、幂等、租约、重试和检查点恢复；真实 DataWorks、真实模型、外部数据库和标签正式发布仍属于后续单独冻结范围。

## 决策

1. 使用 `ScriptDefinition + ScriptVersion` 注册稳定能力键和不可变执行版本。页面和 API 只管理受控元数据、Schema、权限声明、重试策略与制品哈希，不接收 Python、JavaScript、SQL、Shell、源码或命令。
2. 使用 `WorkflowDefinition + WorkflowVersion` 管理不可变 DAG。步骤只能引用已注册脚本版本，条件路由采用受限 JSON DSL；类目通过 Profile 组合标准步骤和参数，不复制平台通用能力。
3. 使用 `ProductionRun + ProductionStepAttempt` 记录通用执行事实，运行创建时冻结工作流、脚本、类目合同、模型/机制引用、队列策略和输入版本，全部按 canonical JSON 与 SHA-256 固化。
4. 通用运行时必须复用现有 `DeterministicQueueScheduler`、`QueueSchedulerState` 和五队列：`validation`、`interactive`、`production_batch`、`canary`、`recovery`。`RuntimeDispatchItem` 只是适配记录，不新增第六队列、配额算法或第二套调度状态。
5. 首批执行器只允许 `deterministic_fixture`。运行支持幂等创建、有限租约、心跳、超时、自动重试、恢复队列和步骤级检查点；已成功步骤在恢复时不得重跑。
6. `EvaluationProductionRun` 与既有评测、纠偏、机制发布和标签发布历史保持不变。新通用运行只通过可选 `source_type + source_id` 关联，不回填、不重写历史。
7. 桌面运行中心一级页面只展示五队列、当前步骤、最后检查点、责任人、阻塞原因和主操作；完整时间线、冻结快照、脚本版本、输入/输出哈希及恢复动作进入二级证据抽屉。

## 结果

- 自动化脚本从散落实现转为可版本化、可验证、可审计的受控能力。
- 各类目可以快插快拔地组合工作流，但仍受统一调度、模型中心、机制、纠偏、发布和投影门禁约束。
- 运行失败可以按冻结快照和检查点恢复，且重复请求不会制造重复运行或重复副作用。
- 未来接入真实执行器时，需要新增适配器和单独冻结凭据、网络、成本、发布与回退合同，不改变本 ADR 的版本和事实边界。

## 不可破坏约束

- 当前环境固定为本地 `dry_run`；不得连接真实 DataWorks、真实模型、真实上游、真实大维表/小表或其他外部数据库。
- 不得上传或执行任意源码、脚本、SQL、Shell 或命令；不得把凭据写入 manifest、快照、检查点或审计事件。
- 不得新增第六队列或第二套调度器；所有调度必须经过现有五队列策略。
- 不得在运行中读取“最新版本”替换冻结快照；版本变化必须创建新版本或新运行。
- 双人工门、机制发布轴和标签事实发布轴继续独立；本批不得自动启用候选、发布标签或执行外部 DML。
- 不得回填或改写历史评测、纠偏、存量回归、机制发布和标签发布事实。
- 未经新的明确授权，不得推送、创建或合并 MR，也不得部署测试服或生产环境。
