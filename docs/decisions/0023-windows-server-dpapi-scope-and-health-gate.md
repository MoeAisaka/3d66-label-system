# ADR-0023：Windows Server DPAPI 存储范围与启动门禁

- 状态：Accepted
- 日期：2026-07-31

## 背景

公司内网 Windows 实例在保存非空 API Key 时返回“API Key 安全存储失败”。
现有实现只使用当前用户范围的 DPAPI，却没有在正式 Windows 部署前执行真实
的加密—解密回环；运行时又把 DPAPI 初始化或加密失败统一压成一条通用错误，
无法区分非原生 Windows、DPAPI 不可用、用户配置文件问题或 Windows 系统错误。

真实 API Key 仍不得进入 SQLite、日志、响应、命令行、临时文件或 Git。本
决策只增强 Windows 安全存储的可部署性与可诊断性，不允许回退到明文、普通
配置文件或可跨机器复制的通用密文。

## 决策

### 显式双范围，不做静默降级

Windows DPAPI 支持两个显式存储范围：

- `current-user`：继续使用当前 Windows 用户范围，引用格式为
  `dpapi:v1:<base64>`；这是安全层 API 的默认值，也继续兼容历史无前缀密文。
- `local-machine`：供受控 Windows Server 启动入口使用，调用
  `CRYPTPROTECT_LOCAL_MACHINE`，引用格式为
  `dpapi-machine:v1:<base64>`。

范围由进程环境变量 `API_KEY_DPAPI_SCOPE` 明确配置，只接受上述两个值及受控
别名。配置非法时关闭失败。当前用户范围失败时不得自动改用机器范围；机器
范围也不得自动退回当前用户范围。

官方 Windows Server 启动脚本默认选择 `local-machine`，并允许操作员显式
改为 `current-user`。核心安全层保持 `current-user` 默认，以免普通交互式
Windows 运行在无感知情况下扩大解密主体。

### 机器范围的安全边界

机器范围解决 Windows Server 服务账户、非交互式启动和用户配置文件不稳定
时的可用性问题，但同机其他主体在同时取得密文和读取权限时也可能调用 DPAPI
解密。因此：

- SQLite 和数据目录必须继续使用公司批准的 NTFS ACL；
- 不把密文写入日志、备份、响应或 Git；
- 正式备份继续清空所有凭据引用；
- 不实现跨机器迁移，换机器后仍必须重新填写 API Key。

### 真实 DPAPI 启动门禁

Windows `doctor` 必须在与服务相同的 Python 进程身份和相同
`API_KEY_DPAPI_SCOPE` 下，使用随机内存哨兵执行一次 DPAPI 加密—解密回环。
哨兵不落盘、不写库、不进日志。回环失败时阻止服务启动，而不是等审核员填写
真实 Key 才发现故障。

数据库中的 `dpapi:v1:`、`dpapi-machine:v1:` 和历史无前缀引用均可在 Windows
通过格式门禁；macOS 和其他平台继续拒绝读取 Windows 引用。

### 脱敏诊断

安全存储异常只暴露稳定原因和 Windows 数字错误码，例如：

- 平台不支持；
- DPAPI 初始化失败；
- 存储范围配置无效；
- DPAPI 加密失败及系统错误码。

日志只记录业务 account、稳定原因和数字错误码；响应、日志和异常都不得包含
API Key、密文或请求体。

## 后果

- 公司 Windows Server 可以在服务启动前证明安全存储可用，减少把真实 Key
  当探针的风险。
- 同一数据库可同时保留历史当前用户范围引用和新机器范围引用；下一次轮换
  Key 时按当前显式范围生成新引用，不需要批量迁移旧密文。
- 机器范围提高服务部署可靠性，但扩大到同机安全边界；其可接受性依赖服务器
  为受控专用主机且数据目录 ACL 正确。
- 仅部署代码不能证明公司实例已经修复；必须在真实 Windows 上看到 doctor
  回环通过，再使用非空 Key 完成保存和连接测试。

## 不可破坏约束

- 不得在 DPAPI 失败后静默回退到明文、文件、环境变量持久化或另一个 DPAPI
  范围。
- 不得在响应、日志、错误信息、数据库、备份、命令行或 Git 中暴露真实
  API Key。
- 不得用测试或 doctor 的随机哨兵覆盖任何已有业务凭据。
- 不得取消 Windows 启动前真实 DPAPI 回环；真实服务器未通过回环时不得宣称
  安全存储已经修复。
