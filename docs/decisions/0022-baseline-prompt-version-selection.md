# ADR-0022：基准回归手选提示词版本与维度版本预留

- 状态：Accepted
- 日期：2026-07-31
- 关联：ADR-0003、ADR-0004、ADR-0020、ADR-0021

## 背景

基准回归已经可以冻结 L1～L5 真值并重复运行，但此前每轮只能自动使用启动时
的已发布 A/B 提示词。审核员无法直接选一个草稿、历史版或待验证版本与同一
基准集做对照，只能先改变线上发布指针，既不便于实验，也扩大了发布风险。

维度管理器后续也需要在相同入口选择维度版本。当前 P1 已把维度合同冻结到
`StrategyBundle`，但维度手选与路由解析尚未实现，不能用一个看似可用的选择器
悄悄忽略用户输入。

## 决策

### 1. 每轮回归明确选择提示词取值方式

创建基准回归 Run 时支持两种方式：

- `当前发布版本`：在启动瞬间解析并冻结当时已发布的 A/B。
- `手动选择版本`：审核员同时指定一个 A 版本与一个 B 版本；草稿、已发布和
  已归档版本均可用于实验，但不会改变线上发布指针。

A/B 必须成对提交，并由服务端校验阶段。不存在的 ID、A/B 阶段错配或只提交
一侧均明确拒绝，不能自动替换成其他版本。

### 2. 仍以 StrategyBundle 作为不可变事实

无论自动还是手选，服务端均使用选定版本创建或复用不可变
`StrategyBundle`。Run、EvaluationJob 与结果继续冻结同一 canonical hash、完整
提示词内容、模型配置、评分规则和维度集合。

Run 列表与详情从冻结策略快照返回 A/B 的 ID、名称、版本和 rubric；前端必须
显示本轮实际使用的版本，不能只显示当前发布指针。

### 3. 维度版本选择先预留、后实现

创建 Run 的请求合同预留 `dimension_schema_id`，响应合同返回当前策略快照内
冻结的维度版本。P2 完成前：

- 前端展示只读的“跟随策略快照”；
- 请求若提交非空 `dimension_schema_id`，服务端返回
  `DIMENSION_VERSION_SELECTION_NOT_ENABLED`；
- 禁止静默忽略、自动降级或伪装成已支持。

后续启用手选维度时，应在不改请求字段语义的前提下，把所选维度版本纳入
StrategyBundle canonical definition，并补充路由、兼容性与跨版本可比性门禁。

## 后果

- 同一冻结基准集可以安全比较不同提示词组合，不必先发布候选版本。
- 历史 Run 会永久显示当时的真实 A/B 与维度快照，后续发布或回滚不改写历史。
- 维度选择入口和 API 已有稳定边界，但当前仍不可手选；用户会看到明确状态，
  不会误以为选择已生效。
- 手选已归档提示词允许复现历史问题，但它只影响新建回归 Run，不会恢复或发布
  该版本。

## 不可破坏约束

1. 手选提示词不得修改任何 PromptVersion 状态或线上发布指针。
2. A/B 必须成对且阶段匹配；服务端不得信任前端标签。
3. 每轮 Run 与其 StrategyBundle、Job、结果必须使用同一冻结提示词身份。
4. 历史 Run 的选择快照只读，不得随当前发布版本变化。
5. 维度手选未正式实现前，非空请求必须 fail-closed，禁止静默忽略。
6. 后续维度手选必须进入 canonical hash、审计与回归对比合同。
