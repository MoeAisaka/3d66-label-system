# ADR-0033：按类目高度自定义的评测底座（红线前置过滤 + 分类 + 维度）与 L 等级方向校正

- 状态：Accepted
- 日期：2026-08-03
- 关联：ADR-0028（可组合类目流水线）、ADR-0029（统一标签生产消费合同）、ADR-0031（类目维度管理与仅提示词模式）
- 输入规则：钉钉《【灵感图】-prompt》（快照 `docs/reference/category-inspiration-image-rules-20260803.md`）
- 讨论稿：`docs/discussion/category-evaluation-base-refactor-20260803.md`

   material_image、pdf_text 幂等复制该合同及各自 A/B prompt，改写 category_key、

2. 完整流水线与基准回归的新任务只读取并冻结 active

4. “类目评测 v3 合同配置”是唯一可路由配置入口；旧“类目与维度”页面退出路由。


## 背景

素材标签会最终落到生产消费闭环（搜索、推荐、前端）。评测流程不仅要产出美感等级，还要产出并纠偏一批固有字段（title/seotitle/category/style/tags/cons/design/reason/image_defects/trait/image_quality/media_form），并且不同类目需要：

1. 一道**前置红线过滤**，命中直接定级、不再评测；
2. 一道**分类**节点，把素材分到不同赛道/子类目，每个赛道用不同维度标准；
3. 每套维度标准里含一项**固定通用维度**（媒介类型：实景/效果图/AI/其它 的固定加权降权）。

现有系统已具备类目流水线（ADR-0028）、维度路由（`material-family-routing`）、类目维度管理与仅提示词模式（ADR-0031）、统一发布消费合同（ADR-0029）。本 ADR 在此底座上，把上述三节点固化为**显式、按类目可配置、入队冻结、可回归**的评测流水线合同，并明确「调用A / 调用B / 维度」的职责边界。

## Owner 决策（2026-08-03，已确认）

1. **L 等级方向以钉钉文档为准：L5 = 最差，L1 = 最优。** 现平台方向写反（L5=最优），需校正。
2. **调用A / 调用B / 维度的职责边界要在前端有明确用法说明**，降低使用者理解成本。
3. **赛道分类（管分数：一类/二类/三类）与 17 类一级标签（管命名）两套并存**，互不替代。
4. **先搭通用框架**（通用底座 + 冻结合同 + 边界），再逐类目填充规则；灵感图作为第一套落地规则集。

## 决策

### 零、最终形态与定位（2026-08-03 Owner 校正）
红线 + v3 合同 + 聚合器**不是长期并列于现有流程旁的另一套引擎，而是「调用A / 调用B / 维度」这三位的重构版本**。最终形态：**完整流水线（full_pipeline）与基准回归（baseline_regression）两条线都收敛到这套重构后的 A/B/维度上**，不再各自散落算分逻辑。

分阶段落地（框架先行只是过渡）：
- **过渡态（当前）**：三件为独立纯函数、已回归、`worker` 未接入。这是为了先把确定性底座验证透，不是终态。
- **终态（Phase 4）**：两条流水线共用的那个算分步骤按**类目合同版本**分流——v3 合同（含 redline/track/common_modifiers）走重构后的 A→B→聚合器；旧任务继续走老 `calculate_score()` 兼容执行。因两条线共用算分步，一次接入两线同时生效；用合同版本而非业务类目名分流（守 ADR-0028）。
- 现有 `dimension_router`（material-family-routing）与维度 Schema **不是被删除，而是变成重构后「调用B→维度扣分」这一步的输入与约束**。

#### 调用B 重构的关键契约：grade → deduction 桥
钉钉文档的算分是**扣分制**（每维度满分 X，命中问题扣 Y）；现有调用B 产出的是 `grade`(1-5)。因此重构后的调用B/维度层之间需要一个**确定性 grade→deduction 桥**：把每个维度的 grade（或其 grade_points）按该维度在子类目中的满分权重，映射为聚合器消费的 `deductions[dimension_key]`。该桥必须是纯函数、可回归、按维度 Schema 冻结，禁止模型自行给"扣多少分"。这是 Phase 3.5 的框架产物，先于 worker 接线。（已交付：`dimension_grade_bridge.py`）

#### 权威流水线定义（2026-08-03 Owner 补充，以此为准）

完整评测链：
```
红线筛查（直接筛掉 L5）
  → 分类器（类目 → 子类目）
  → 子类目：提示词 A/B 评测
  → 维度评测（子类目共性维度 + 子类目特有维度）
  → 产出评测结果（等级 + 分数 + 固定字段）
```

对前面建模的两处校正：
- 我先前用的“赛道/track”**就是分类器产出的子类目**；正名为 classifier → 子类目（sub_category）。track_classification 合同块语义不变，后续命名向“子类目”靠拢。
- 维度**不是每子类目一套 schema，而是「共性维度 + 特有维度」两组**：
  - **共性维度**：跨子类目共享（对应现有 schema 的 `core_dimension_keys`）。
  - **特有维度**：每子类目自定义。
  - v3 合同的每个子类目因此需要**两个维度引用**（common_dimension_schema_ref + specific_dimension_schema_ref）而非单一 `dimension_schema_ref`；两组维度合并后的权重和=1，共同占满该子类目的 `dimension_max`。（待 Phase 3.6 扩合同与桥）

**维度可自由增删与开关（2026-08-03 Owner 补充）**：共性维度与特有维度**都可自由增删、开关，数量不强制固定，两组都可为 0**。实现铁律（Phase 3.6 已实现）：
- 非空组的 `group_weight` 在**非空组之间重归一化**并平分 `dimension_max`（沿用 ADR-0028 `renormalize_selected_to_one`）；一个空组**不保留任何分额**，绝不把空组的分数当白送分泄露给成统。
- 两组都为 0 → **仅提示词模式**（`dimensions_enabled=False`）：不产维度分，`deductions` 为空；对齐 ADR-0031 仅提示词模式（否则应路由到仅提示词评分合同，不得默认白送满分）。
- 非空组必须携正 `group_weight`；空组的 `group_weight` 忽略。grade→deduction 数学不变。
- 固定通用维度（媒介降权/高分压分）仍属 `common_modifiers`，与“共性维度”是两回事：前者是服务端确定性规则，后者是调用B 打分的维度。

#### 两条流水线只差数据源（Owner 铁律）

完整流水线与简易流水线（基准回归）**只差输入数据源，评测能力必须完全一致**：
- **完整流水线**：增量**未定性**素材（上游持续产生的新内容）。
- **简易流水线/基准回归**：存量**已定性**素材（冻结人工真值，用于准确率/回归）。
- 两者走**同一套红线+分类器+A/B+维度+聚合器**，绝不允许两套实现。这正是聚合器/合同必须是**唯一共享引擎**的根据，Phase 4 接线时两线共用同一算分步。

### 一、评测流水线合同（通用底座）

在 ADR-0028 的 `evaluation-category-profile` 上升版本到 **v3**，新增三块可配置、入队冻结的定义：

1. `redline_policy`（红线前置过滤，节点0）
2. `track_classification`（赛道分类，节点1，管分数基底与封顶）
3. `common_modifiers`（固定通用维度：媒介降权 + 高分一票压分，跨赛道生效）

一级/二级标签命名（17 类）作为**独立于赛道的标签产出**，挂在调用A的生产字段（`category`）上，不参与赛道计分选择。两套并存、互不耦合。

执行顺序（不可跳级，任一前置节点短路则终止）：
```
调用A（分类+红线信号+生产字段）
  → 红线判定（确定性）：命中 → 直接定级 + hard_reject → 终止
  → 赛道分类（确定性映射）：选定维度Schema + 基底分 + 赛道封顶
  → 调用B（按赛道维度Schema逐维评审）
  → 维度层（确定性聚合）：基底分 - 维度扣分 - 媒介降权 → 高分一票压分 → 赛道封顶 → 最终 score + L 等级
```

### 二、三位置职责边界（钉钉点名要理清；前端必须显性说明）

| 位置 | 唯一职责 | 输入 | 输出 | 明确禁止 |
|---|---|---|---|---|
| **调用A（预检/分类，模型）** | 客观事实：红线信号、媒介类型(trait)、赛道判定信号、生产字段、初步参考 score | 图片 | `production_fields` + `classification`(赛道信号) + `media_form` + 红线证据 | 不出维度分、不出最终 L 等级、不做加权/封顶 |
| **调用B（维度评审，模型）** | 主观质量分档：仅对未被红线淘汰者，按赛道维度 Schema 逐维打 grade+证据+缺陷 | 图片 + 冻结维度 Schema | `dimensions` + `special_checks` + confidence | 不出总分、不出最终 L、不做红线判定、不做媒介降权 |
| **维度层（服务端，确定性）** | 把 A/B 输出按冻结合同算成 score + L 等级 | A + B 结构化输出 | 最终 score + L + cap_reasons + hard_reject + 命中红线 | **不调用模型**（纯函数、可回归、可复现） |

记忆口径：A 看「是什么、有没有硬伤」，B 看「做得好不好」，维度层「确定性地算分和定级」。红线与媒介降权是**规则**，必须在服务端确定性层，禁止塞进 B 的提示词让模型自觉。

前端在类目配置页对三个填写位（调用A提示词 / 调用B提示词 / 维度Schema）给出固定说明文案、placeholder 和校验，并在结果/纠偏页显式标注每个字段来自哪个位置。

### 三、红线规则集（`redline_policy`）

- **红线规则可自由增删、开关，数量无限制（2026-08-03 Owner 补充）**：`rules` 是列表，条数不限；每条规则支持独立的 `enabled`（可选，默认 true）开关——可保留规则但临时关闭。启用红线阶段但零规则（或全部规则关闭）是合法的，只是永不命中；与维度组可为 0 的放宽一致。

- 确定性匹配，命中即淘汰；信号**优先复用调用A已产出的 `reason` 枚举**（是截图/有大面积文字说明/是多拼图/有二维码/是随手拍/是颠倒图），不新造模型输出通道。
- 每条规则含 `key`、`match`（reason 枚举/其他A字段）、`exemptions`（豁免）。
- 命中动作：`hit_level="L5"`（按 Owner 确认的文档语义，L5 为最差/废图档）+ `hard_reject=true` + `score` 封顶到 `hit_score_cap`（文档 ≤49）+ 记录命中规则 key。
- 灵感图首套红线：截图、随手拍（透视杂乱）、大面积文字(≥40%，豁免专业海报/轻量化效果图辅助文字)、大面积二维码(≥50%，豁免角落极小)。

### 四、赛道分类与固定通用维度

- `track_classification`：类目自定义赛道集合、每赛道的「维度 Schema + 基底分 + 赛道封顶」。灵感图三赛道：一类(建筑/室内/景观/规划,基底40,六维60,上限100)、二类(产品/雕塑/装置/美术/游戏原画,基底20,六维60,上限80)、三类(其他杂图,基底40,五维30,上限70)。复用并扩展 `dimension_router`，赛道→Schema 从类目合同读取，不再全局硬编码五族。
- `common_modifiers`：
  - `media_type_penalty`：以实拍为基准，效果图 -5，AI 图在效果图基础再 -10（相对实拍 -15），其它 0。来源 `production_fields.trait`。
  - `high_score_veto`：分数 ≥80 命中任一硬伤清单 → 强制封顶 79，记 cap_reason。

### 五、L 等级方向校正（高风险，独立迁移工作流）

Owner 决策 L5=最差、L1=最优，与现平台相反。校正范围（blast radius）如下，**必须作为独立、可回滚的迁移工作流处理，不得在框架搭建期静默翻转**：

1. `scoring._level_for_score` + `LEVEL_THRESHOLDS` 方向；`dimension_schema_registry` / `dimension_route_registry` 的 `_LEVEL_THRESHOLDS`、`cap_rank`、caps 语义（现有"效果图进入L5""L5需要五个5级维度"等逻辑全部按新方向重写）。
2. 已发布标签（`PublishedLabel`）与消费接口（ADR-0029 `/api/consumer/v1/labels`、Outbox）中已落库的 L 值——**历史发布不可原地改写**（ADR-0029 不可破坏约束）。方案：引入 `level_semantics_version`，旧版本标签保留原语义并标注，新发布用新语义；消费方按 `level_semantics_version` 解释，避免搜索推荐读到混合方向。
3. 回归基线、二审证据、人工真值中的 L 值：冻结快照保留其 `level_semantics_version`，回归对比同语义版本，不跨版本直接比较。
4. 前端所有 L 等级展示、颜色、排序、阈值编辑器同步校正，并显示当前语义版本。

迁移门禁：新语义上线前必须通过专门的回归门禁（含红线直出档），并对历史发布标签完成语义版本标注与消费方兼容验证。

### 六、与仅提示词模式共存（ADR-0031）

红线节点独立于维度评分：`维度 enabled=false`（仅提示词）时红线仍可生效，直接产出淘汰档；此时不产出维度分。红线命中属于 ADR-0028 后果中「无维度直出等级」，走独立评分合同与回归门禁。

## 后果

- 任意类目可通过配置定义红线、赛道、维度和通用降权，新增类目不改业务代码。
- A/B/维度边界清晰且前端可见，降低使用与配置的理解成本。
- L 方向校正为一次性、可回滚、带语义版本的迁移，历史发布不被破坏。
- 通用框架先行，灵感图作为首套规则验证底座。

## 不可破坏约束

1. 已入队任务冻结完整 v3 合同（红线/赛道/维度/通用降权/L语义版本），后续改配置只影响新任务。
2. 红线与媒介降权是服务端确定性逻辑，禁止依赖模型提示词自觉；纯函数可回归。
3. 禁止模型覆盖人工真值、禁止绕过二审发布（延续 ADR-0029/0031）。
4. L 方向校正禁止原地改写历史 `PublishedLabel`；以语义版本 + 新发布实现，回滚为新发布而非删除。
5. 赛道分类与 17 类一级标签两套并存，互不替代、互不耦合。
6. 类目只能组合已发布的维度 Schema、处理器与节点能力；新增底层能力仍走维度管理/校准/工程发布门禁。

## 落地节奏（框架先行）

1. 冻结合同 schema v3（redline_policy / track_classification / common_modifiers / level_semantics_version）+ 迁移脚手架 + `PRAGMA foreign_key_check`。
2. 服务端确定性层：`redline_policy.py`（纯函数）+ 收敛 `scoring` 聚合器（基底分→维度扣分→媒介降权→高分压分→赛道封顶→L等级），全部带 cap_reasons/hard_reject。
3. 赛道路由扩展：`dimension_router` 从类目合同读赛道→Schema 映射。
4. L 方向校正迁移工作流（独立分支、独立回归门禁、语义版本、历史发布兼容）。
5. 前端：类目配置页（红线/赛道/通用降权编辑 + 三位置说明文案）、结果/纠偏页（红线命中/hard_reject/降权/压分明细 + L语义版本）。
6. 灵感图首套规则填充 + 端到端回归。
7. 全程小步提交，后端 pytest 全绿、前端 build 通过，每步可回归。
