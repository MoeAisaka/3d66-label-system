# ADR-0045：TPENG 标签实验台双工作区与数据库表投影合同

## 状态

已接受（2026-08-13）

关联：ADR-0041（标签机制与模型管理执行合同）、ADR-0042（统一产品载体）、ADR-0043（Canonical 事实与资产语义投影边界）、ADR-0044（工作区与机制 profile 插件边界）。

## 背景

TPENG 标签实验台（LabelLab）已经是标签体系重构的统一产品载体，也是标签/内容中台重构的通用底座，
不再与“标签体系重构”并列为两套项目。产品需要同时承载新进入、未定性素材的增量生产链路，以及已定性
存量素材的回归、纠偏和重跑链路；下游实际消费形态是一个统一大维表和数个职责明确的小表。

如果仅把两条链路堆叠在同一页面，会混淆任务上下文和人工门禁；如果由每个类目或每张下游表复制一套
生产能力，又会破坏平台复用、事实主权、版本追溯和模块化快插快拔目标。因此需要冻结产品壳、共享平台核、
类目插件和数据库表投影之间的边界。

## 决策

### 1. 产品壳与双工作区

- 一级产品壳固定提供增量评测、存量回归、运行中心、质量资产、治理与发布入口。
- 增量工作区按“类目 → 接入/素材包 → 机制 → 评测 → 人工纠偏 → AI 候选与回归 → 人工发布”串行推进。
- 存量工作区按“类目 → 存量包/黄金集 → 机制 → 回归 → 人工纠偏 → AI 候选与回归 → 人工启用 → 存量重跑/发布”串行推进。
- 两条链路页面和任务上下文隔离，但共享素材、模型、机制、纠偏、AI 迭代、黄金集、发布、投影和运行调度平台内核。
- 一级页面只保留主线状态、必须的决策证据和动作；复杂配置、历史、矩阵、失败样本和诊断进入二级抽屉、Dialog 或专用工作台。

### 2. 共享执行内核

- 增量与存量任务共用五类队列、并发配额、空闲借用、分级重试、熔断和恢复证据，但必须保留明确的 `workflow_kind` 或可确定推导的任务来源。
- 本地 `content-ingress-v1` 事件可按类目和现役 profile 校验后幂等创建 `production_import` 增量素材包；重复事件复用原包，缺素材或 profile 不可执行时 fail-closed。
- 接入事件不自动创建评测 Job，不代表真实上游已连接，也不能绕过人工发布门禁。

### 3. 类目 profile 是唯一扩展边界

- 类目只提供输入输出合同、提示词、维度、规则、门槛和专用编辑视图，不复制平台模型管理、纠偏、AI 迭代、发布、重跑和对账能力。
- 标准图像和 Proposal PDF 是当前可执行 profile；3D、SU 只预留受控专用编辑器槽。
- 未知、版本不兼容或未启用 profile 只允许只读摘要和 JSON 诊断，禁止写入、创建候选和启动执行。

### 4. Canonical 事实与数据库表投影

- `semantic.*`、`quality.*`、`governance.*`、人工真值、证据、来源、机制/模型/规则版本、审核与发布状态属于中台 Canonical 事实。
- 下游默认采用一个统一大维表和数个职责小表。大维表承载稳定宽字段读取；小表承载搜索标签、质量过滤、治理来源、变更事件或类目专用字段。
- 所有表只读取正式发布标签事实，不读取候选机制、实验结果或人工处理过程；表投影不能反向覆盖 Canonical 事实。
- Projection Contract Registry 必须定义字段映射、来源命名空间、输入标签版本、幂等键、资产版本、机制版本和模型版本。
- Manifest 与对账必须覆盖行数、缺失、版本匹配和确定性哈希；失败只记录差异并重试/补偿，不改写 Canonical 事实。

### 5. 双发布轴和人工门禁

- 机制发布轴与标签事实发布轴继续独立。
- AI 自动生成完整候选机制和候选回归证据，但候选只能由具备权限的人工启用或拒绝。
- 启用机制不自动覆盖存量标签；存量重跑和正式标签发布仍需独立人工动作与审计。

## 当前实施批次

本批实现：

- 增量/存量双工作区和共享步骤组件；
- 显式工作流上下文、本地接入幂等组包、运行中心证据；
- 黄金数据集管理和 CSV/JSON/Manifest 导出；
- 字段级准确率、召回率、混淆矩阵和失败样本证据；
- 受控类目 profile 注册表及 3D/SU 只读预留槽；
- 一个统一大维表和数个小表的 Registry、Manifest、本地模拟适配器与对账合同。

本批不实现或不授权：

- 连接真实上游、搜索/推荐、知识图谱或真实公司业务数据库；
- 向统一大维表或小表执行真实物理写入；
- 生产级多实例投影服务、Embedding 生命周期或大规模存量 Worker；
- 3D/SU 专用业务编辑器、候选自动采纳、新权限或移动端验收；
- Codeup 推送、合并或部署到 `192.168.1.35:8081`。

## 后果

- 增量与存量可以独立验收和串行引导，同时共享平台能力和运行资源。
- 类目与下游消费场景只增加合同和投影，不复制一套标签生产系统。
- 本地模拟适配器可以验证版本、哈希和对账关系，但不能被描述为真实业务数据库已接通。
- 下一阶段必须由【标签体系】重构 Owner 根据 Gap 清单重新冻结目标、范围、权限、回退和验收；冻结后仍由 TPENG 标签实验台会话作为唯一代码写入方。

## 不可破坏约束

- TPENG 标签实验台始终作为标签体系重构的单一产品载体和中台底座规划。
- TPENG 标签实验台始终覆盖接入、生产、纠偏、迭代、发布、消费和回流完整闭环。
- 不让下游表、索引、向量或图谱成为 Canonical 事实主库。
- 不自动启用候选机制、不自动发布标签事实、不把机制启用等同于存量覆盖。
- 不因本 ADR 扩大当前权限、生产操作、外部接入、非目标或验收条件。
