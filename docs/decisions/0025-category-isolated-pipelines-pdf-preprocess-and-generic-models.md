# ADR-0025：多类目隔离流水线、PDF 前处理与通用模型渠道

## 状态

已接受，2026-08-01。

## 背景

实验台将继续接入空间图片、动图、PDF 方案文本和材质图。不同类目的输入形态、
前处理、Prompt、维度规则和模型可能不同；若共用可变的全局配置，重试和历史结果
会出现规则漂移。主模型与横评模型也需要验证多个 OpenAI-compatible 渠道，不能把
火山方舟或 SOL 写成固定实现。

## 决策

1. 以 `EvaluationCategoryProfile` 作为类目边界。`category_key` 随素材包、Job、
   重试链和结果策略快照持久化；类目配置只影响新任务，历史任务使用冻结快照。
2. `pdf_text` 进入 Worker 前必须完成内容哈希缓存的文本抽取、页图接触表渲染和
   可选 OCR，并记录 `ocr_status`、页数和字符数。OCR 不可用时明确记录状态，不能
   把未处理内容伪装成已完成；原 PDF 不覆盖。
3. GIF 与普通图片共用评分规则，但发送给模型的是最多四帧的确定性 PNG 接触表；
   页面继续展示原始 GIF。
4. 模型配置的 `provider` 是自由渠道标识，连接地址、路径、模型 ID 和凭据独立配置；
   Worker 只依赖兼容 Chat Completions 合同，不把渠道名写死为 doubao 或 sol。
5. 类目配置页面用业务字段呈现前处理参数和 Prompt/模型绑定，避免要求操作员直接
   编辑原始 JSON；底层仍保留 JSON 快照以便审计和回放。

## 迁移与兼容

- 迁移 v31 新增类目表及 `category_key` 字段。
- 迁移 v32 修复已应用 v31 但种子为空的数据库，并对缺少历史外键表的部分数据库
  安全跳过种子写入；API/Worker 对旧的直接构造调用提供空间图片默认合同。
- 迁移 v33 冻结评测前处理证据；迁移 v34 为 Job 增加完整类目执行合同快照。
  快照只保存非密模型参数和模型配置 ID，执行时按 ID 读取当前系统凭据引用，绝不
  保存 API Key、密文或系统凭据内容。
- 不重算历史结果，不把旧素材包自动转换成 PDF 或材质图。

## 验收门禁

- PDF 坏文件、文本抽取、OCR 状态、页图缓存和 Worker 上下文均有测试。
- PDF 与材质图 MIME/类目隔离、重试保留类目、Profile 绑定和通用 provider 均有
  合同测试或静态构建验证。
- 推送前必须 `git diff --check`、后端全量测试、前端 lint/build，并用
  `git ls-remote` 核对 Codeup 历史；禁止 force push。

## 后果

- 新增类目不再只改上传白名单，必须同时定义前处理、Prompt、维度和模型合同。
- 结果与缓存体积会增加，但换来可回放的输入证据和跨渠道质量对比能力。
- OCR 是可选增强而非静默依赖；缺少本地 OCR 时仍可用 PDF 原生文本和页图评测，
  但结果页必须明确标记 OCR 不可用。

## 不可破坏约束

- 禁止在重试时重新读取另一类目的活动配置。
- 禁止覆盖原始 PDF/GIF，所有派生文件必须按内容哈希缓存。
- 禁止因 provider 名称未知而拒绝 OpenAI-compatible 端点；端点能力应由连接测试和
  结构化响应校验决定。
- 禁止把未执行的 OCR、多模态总结或模型调用标记为成功。
