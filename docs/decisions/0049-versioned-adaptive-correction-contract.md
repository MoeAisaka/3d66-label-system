# ADR-0049：版本化纠偏合同与自适应纠偏面板

## 状态

Proposed（2026-08-18，本地实现与自动化验收完成；真实浏览器/测试服验收待发布窗口）

## 背景

纠偏页面此前包含部分动态维度，但生产字段和等级撮合器细节仍可能来自固定前端条目。机制版本增加、删除或改变节点后，运营会看到过时的纠偏表单，无法修正新机制实际使用的字段或规则判断。

## 决策

1. 每个机制版本必须携带不可变的纠偏合同，描述维度、生产字段、调用 A/B 节点和 v3 等级撮合节点的稳定标识、类型、中文说明、证据要求与服务端重算引用。
2. 每次增量、存量或候选回归都冻结该合同及其哈希；纠偏页只按回归快照渲染，不读取当前现役版本覆盖历史证据。
3. 运营纠正样本上的规则判断、理由和证据；AI 根据结构化证据生成调用 A、调用 B 或 v3 候选，运营不直接编辑全局规则代码或阈值。
4. 跨版本只继承稳定标识、类型和语义兼容的人工结果；新增节点待确认，删除节点只留历史，语义变化不继承。
5. 缺少完整纠偏合同的候选不得启用；历史合同不足时只读降级，禁止使用现役合同猜测补齐。
6. 存量回归、增量审核和候选回归共享同一合同渲染器与服务端校验边界。

## 后果

- 新机制的新字段和新等级规则可在新一轮纠偏中立即出现，不再因固定表单漏项。
- 历史回归可稳定复盘，合同变更不会污染旧人工证据或评分解释。
- 机制候选需要同时维护运行合同和纠偏合同，版本发布前的校验成本增加。
- 前端不再拥有业务字段清单；复杂 v3 规则必须由后端提供可读节点描述。

## 不可破坏约束

- 不改写历史评测、人工审核、模型原始响应或人工真值。
- 不让浏览器执行或提交规则代码；服务端评分引擎是唯一重算权威。
- 不自动启用候选、不触发标签事实发布或存量重跑。
- 旧合同缺失时不读取现役合同补齐，不静默隐藏不可纠偏节点。
- 机制发布轴与标签事实发布轴继续独立，NAS 存储迁移不属于本 ADR。

## 验收与回退

连续机制版本的增删改节点、三条链路共享渲染、跨版本继承、v3 重算、过期合同拒绝和历史兼容测试全部通过后，才可把状态改为 Accepted。实现采用增量迁移和独立提交；发现重算不一致、合同语义不明或并行冲突时回退提交并停止外部交付。
