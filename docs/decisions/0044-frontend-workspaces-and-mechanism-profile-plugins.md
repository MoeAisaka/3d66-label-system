# ADR-0044：TPENG 标签实验台工作区与机制 profile 插件边界

## 状态

已接受（2026-08-12）

关联：ADR-0041（标签机制与模型管理执行合同）、ADR-0042（统一产品载体）、ADR-0043（Canonical 事实与语义投影边界）。

## 背景

TPENG 标签实验台（LabelLab）作为标签体系重构的统一产品载体和标签/内容中台通用底座，已同时承载素材接入、类目评测、人工纠偏、AI 迭代、版本治理、存量回归和正式消费。此前多个页面把主操作、复杂配置、历史、指标和证据平铺在同一层，导致主线不突出，也容易让类目差异被误解为平台能力复制。

## 决策

### 1. 工作区信息架构

- 一级页面只保留当前操作主线所需的决策信息、状态摘要、筛选和高频动作。
- 复杂配置、历史轮次、指标、原始证据、诊断和帮助信息进入宽抽屉、Dialog 或独立工作台。
- 合同编辑和逐条纠偏使用独立工作台；工作台必须提供清晰的返回主线动作，必要时使用 URL 参数恢复上下文。
- 抽屉/Dialog 复用统一焦点返回、遮罩、键盘关闭和桌面端尺寸契约；不以移动端布局作为本系统验收目标。

### 2. 机制 profile 插件

- 类目专用机制通过受控 `profile_type` 注册表扩展，平台只负责注册、路由、校验、版本快照和安全降级。
- 标准图像机制与 Proposal PDF 机制保持独立合同和独立编辑器；Proposal PDF 不套用图像 bonus/cap 数学。
- 3D、SU 等未来类目只接入受控插件注册和安全降级；本 ADR 不授权实现专用编辑器。
- 未知机制允许只读摘要和 JSON 诊断，写入必须 fail-closed；不得执行任意前端或后端代码插件。

### 3. 版本与发布边界

- 现役 V3 合同行是运行时 active 投影；编辑操作只创建不可变 candidate revision，不得原地覆盖 active。
- 普通合同更新、level-scale 更新和 status 更新都不得绕过既有人工发布门禁、权限和审计要求。
- 机制发布轴与标签事实发布轴继续独立；机制启用不自动触发存量重跑或标签事实覆盖。
- 下游只消费正式发布事实，不读取候选机制、实验结果或人工处理过程。
- 旧冻结合同在读取时不因默认字段或新 composition 版本而改变数学语义。

### 4. 本批次不扩大

以下内容是架构 Gap，不是本批次隐藏实现步骤：

| Gap | Owner | 下一阶段冻结输入 |
|---|---|---|
| candidate revision → candidate-aware regression snapshot | 标签体系 | 候选绑定、快照结构、回归门禁 |
| regression evidence → `EvaluationPackage` manifest binding | 标签体系 | 证据清单、manifest 版本和验收关系 |
| approved package → atomic active projection switch + `MechanismRelease` | 标签体系 | 原子切换、权限、回退和观察窗口 |
| append-only rollback release → prior revision projection restore | 标签体系 | 追加式 activation revision、恢复条件和审计 |

本批次明确不实现：其他路由的全面重构、3D/SU 专用编辑器、生产发布、真实存量批量重跑 Worker、候选自动激活、真实模型批量调用、Embedding 生命周期、通用语义投影 registry、外部下游写入或新权限。

## 后果

- 后续页面可以复用统一工作区、抽屉、Dialog 和工作台模式，减少“一级页面平铺所有内容”。
- 类目团队只提交自身合同、规则、维度、提示词和展示差异，不复制平台模型、纠偏、版本治理、重跑和发布能力。
- 候选 revision、回归证据和发布投影的绑定关系仍需 Owner 单独冻结，不因本 ADR 自动进入生产。

## 不可破坏约束

- 不重新拆分“标签体系重构”和“标签实验台”为两条独立项目线。
- 不把 TPENG 标签实验台描述为仅用于评测、打分或提示词实验的工具。
- 不以工作区重构为理由改变权限、发布门禁、双发布轴、回退或当前验收条件。
- 不让候选机制、实验结果或人工过程成为下游正式事实消费入口。
