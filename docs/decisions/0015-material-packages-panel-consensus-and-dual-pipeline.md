# ADR-0015：素材包、初审组共识与实验台—生产平台双流水线

- 状态：Accepted
- 日期：2026-07-29
- 取代：ADR-0014 中“样本初审→样本二审→样本仲裁”的主流程语义

## 背景

Owner 明确实验台与生产平台不是两套互不相干的后台。实验台负责可追溯评测、
人工真值、提示词优化、配对回归和版本发布决策；生产平台负责自动接入新素材、
自动评测、低置信度人工纠偏以及已批准策略的金丝雀和实装。生产纠偏必须先解决
线上数据，再以不可变事件回流实验台，不得反向同步覆盖历史运行。

ADR-0014 把同一图片的人工处理拆成初审、二审、仲裁。最新产品语义要求：
奇数审核员在“初审组”内独立盲审并形成最终真值；“人工二审”审核的不是图片，
而是提示词候选及其回归证据。因此旧二审/仲裁只能作为兼容历史，不能继续作为
主导航和新任务状态机。

## 决策

### 素材包与任务选择

- 每次批量上传产生不可变 `MaterialPackage`，即使图片因 SHA-256 去重复用既有
  `Asset`，也要在包内保留一条 `MaterialPackageItem` 来源记录。
- 素材包可按上传时间筛选，展示新增数、重复数和任务状态汇总。
- 人工可从素材包或筛选结果选择图片创建评测任务。默认排除“已用当前策略版本
  完成评测”的图片，但允许显式复测。
- 素材状态至少区分：未评测、仅旧版本评测、当前版本已评测、排队、运行、失败。
  状态是指定策略组合下的派生视图，不写回 `Asset` 成为唯一评测结论。

### 受控 Multi-Agent 快照

- 每次初评固定绑定
  `PromptVersion + AgentPlanVersion + Model + Rubric + Engine`。
- `AgentPlanVersion` 是受控、版本化编排，不允许运行时自由增删角色。
- StrategyBundle 与结果快照必须包含 AgentPlan 版本；变更任一项都形成新候选
  组合并重新验证。

### 初审组与最终真值

- 低置信度结果进入一个 `ReviewPanel`。全局 `ReviewWorkflowPolicy` 可配置
  1、3、5、7、9 人；初期默认 1 人，后续按实际团队规模切换为奇数多人组。
- 初审组创建时必须快照 `required_reviewers`。全局人数调整只影响之后创建的
  面板，不得改变正在进行或已完成任务的审核人数和历史结论。
- 1 人模式下，唯一审核员提交后即在初审阶段形成最终人工真值，不再人为制造
  二审或仲裁节点；同一人员可以继续处理优化回归与提示词发布决策。
- 3 人及以上模式下，审核员独立盲审，提交前后都不得在面板关闭前看到其他人的
  具体答案。
- 只有收齐面板创建时冻结的全部审核席位后才允许结算；即使部分字段已提前
  达到严格多数，也必须等待其余冻结席位完成独立盲审。
- 收齐全部冻结席位后，每个维度及关键字段分别计算严格多数；全部字段均有
  严格多数时形成初审组最终真值，仍有字段没有严格多数时进入同一个初审
  工作台内的“主审裁决”子状态，不得转入样本二审队列。
- 投票、裁决和最终真值事件只追加；面板修订使用乐观锁。
- 迁移前的 `secondary / arbitration` 记录只作为历史展示；新任务不再进入
  `secondary`。

### 优化队列、回归与策略二审

- 初审最终纠偏以幂等键写入 `OptimizationCaseQueue`。
- 达到配置阈值或出现 P0/P1 错误时，可自动创建候选并编排目标错例、稳定对照、
  盲测保留三角色配对回归。
- 自动编排必须有预算、冷却、最大候选数、幂等与失败恢复；自动流程只到
  “待策略二审”，绝不自动发布。
- “人工二审”改为提示词发布决策工作台，展示优化诊断、候选差异、回归结果、
  准确率、P0/P1、成本和风险。只有回归通过且人工批准后才允许显式发布。

### 提示词版本指标

- `sample_accuracy = 1 - corrected_sample_count / reviewed_sample_count`。
- 同时提供逐维准确率、等级准确率、审核覆盖率和样本量 N。
- 未完成人工初审的样本不能计为正确；指标必须绑定提示词版本及冻结任务集或
  明确的任务批次，禁止用全部未审核运行稀释纠偏率。

### 前端信息架构收束

- 前端必须围绕完整流水线重新组织多级导航，不能继续把素材、任务、审核、
  提示词和回归作为彼此割裂的平铺页面叠加。
- 一级 Tab 表达稳定的阶段或工作域；二级 Tab 表达该节点下的队列、任务、
  证据或决策视图。建议一级结构为：
  1. 素材与任务：素材包、素材选择、评测任务；
  2. 初评与初审：模型初评、低置信度待审、初审组共识、主审裁决、已完成；
  3. 优化与回归：纠偏案例队列、候选提示词、小样本配对回归；
  4. 二审与版本：待发布决策、版本指标、版本历史与回滚；
  5. 模型实验：Sol/Terra/Luna 横评、迁移证据与生产候选；
  6. 系统治理：模型配置、金丝雀、审计和其他低频管理入口。
- 同一业务对象在各节点必须显示当前状态、上一步证据、下一步动作及阻塞原因；
  已处理、处理中、待人工、待回归和待发布不得只靠用户跨页面自行判断。
- “人工初审”和“提示词二审”属于不同对象、不同责任与不同决策语义，必须位于
  对应流水线节点，不能共用一个审核入口或仅靠页面内筛选区分。
- 路由与 URL 应反映一级/二级层级并支持深链；历史平铺路径可重定向兼容，但不再
  作为主导航。重构只改变信息架构和交互组织，不改变既有只追加历史、乐观锁、
  盲审隔离及发布门禁。

### 生产反馈与模型横评

- 生产纠偏先写生产真值，再以不可变 outbox 事件回流实验台优化队列。
- 正式提示词版本保留回滚指针和金丝雀状态；实验台不直接写生产数据库。
- Sol、Terra、Luna 横评必须在同一冻结样本、Prompt、Rubric、Engine 上进行。
  先验证多模态/API 契约，再比较质量、P0/P1、低置信度/人工率、p50/p95、
  模型成本、含人工审核总成本和重试稳定性。
- 选择先过质量硬门槛，再比较 Pareto 前沿和综合成本；低价不能抵消未过线质量。

## 兼容迁移

- 保留 ADR-0014 的内联纠偏、审核事件只追加、乐观锁、历史样本安全预览和
  发布前配对回归门禁。
- 旧 `secondary / arbitration` 数据保持可读，不原地篡改历史。
- 新评测只创建 `ReviewPanel`；主导航移除样本二审与样本仲裁入口。
- 旧已完成审核可参与历史统计，但必须标记 `legacy_review_chain`，不能伪装为
  三人盲审共识。
- 旧系统尚未配置审核人数时迁移为 1 人默认值；所有已创建面板继续使用自身
  `required_reviewers` 快照，不做批量改写。

## 后果

- 初审工作台解决图片真值，策略二审工作台解决版本发布，两个队列不再混用。
- 素材包和策略相对状态让人工可以安全批量启动任务，又不破坏 Asset 1:N Result。
- 自动优化能减少机械操作，但付费调用、预算和发布权限仍可控。
- 生产平台可以渐进接入，不需要与实验台共享数据库。

## 不可破坏约束

- 不得把素材评测状态固化为 `Asset` 的唯一结论。
- 不得向未提交当前面板投票的审核员泄露其他人的盲审答案。
- 审核人数只能是 1、3、5、7、9；偶数和 0 必须由 API 与数据库双重拒绝。
- 全局人数配置变更不得重写既有面板的人数快照。
- 初审组不得在收齐全部冻结席位前提前结算。
- 最终真值必须在初审工作台闭环；样本二审不能重新成为主流程。
- 未审核样本不得计入准确率分子。
- 自动优化不得自动发布，实验台不得直接写生产数据库。
- 模型横评不得改变冻结样本、Prompt、Rubric 或 Engine 来制造优势。
