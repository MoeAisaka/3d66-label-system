## 0. 一句话结论

我们**不是从零做**。现有代码库已经有类目流水线（ADR-0028）、维度路由（`material-family-routing`）、类目维度管理与仅提示词模式（ADR-0031）、生产维度合同和统一发布合同（ADR-0029）。这次重构的本质是：**把「红线前置过滤 → 分类 → 按类目维度评分（含固定通用维度）」这条链，从现在隐式散落在 schema_adapter/dimension_router/scoring 里的逻辑，提升为一个显式、按类目可配置、可冻结、可回归的「评测流水线合同」**，并把「调用A / 调用B / 维度」三者的职责边界钉死。

前后端都要动，但更多是**在既有底座上补齐红线节点 + 收敛配置模型 + 明确边界**，不是推倒重来。

## 1. 已确认：L5 是最差，L1 是最优

钉钉文档说「命中红线的素材直接产出**等级 L5**，不再评测」。

但现在平台里 L 等级方向是反的（`scoring.py:_level_for_score`）：

| 分数区间 | 平台等级 | 含义 |
|---|---|---|
| ≥90 | **L1** | 最优 / 首页推荐级 |
| 75-90 | L4 | 优良 |
| 60-75 | L3 | 合格 |
| 40-60 | L2 | 偏弱 |
| <40 | **L5** | 最差 |

也就是说：**文档里的「L5=红线废图=最差」和平台里的「L5=最优」正好相反。** Owner 已确认按钉钉文档执行，需要做带 `level_semantics_version` 的独立迁移，不能覆盖历史发布标签。

## 2. 目标业务链（对齐文档）

```
上传素材
  │
  ▼
┌─────────────────────────────────────────────┐
│ 节点0 · 红线前置过滤（按类目可配，硬淘汰）        │
│   命中任一红线 → 直接定级 L5（最差） │
│   + hard_reject=true + 记录命中的红线规则         │
│   → 终止，不再进入分类和评分                       │
└─────────────────────────────────────────────┘
  │ 未命中
  ▼
┌─────────────────────────────────────────────┐
│ 节点1 · 分类（分赛道/子类目 + 一级/二级标签）     │
│   赛道决定：用哪套维度 Schema、基准基底分、赛道封顶 │
└─────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────┐
│ 节点2 · 维度评分（按子类目不同维度标准）          │
│   含【固定通用维度】：媒介类型（实景/效果图/AI/其它）│
│   → 固定加权降权（效果图-5、AI在效果图基础再-10）   │
│   + 高分一票压分铁律（≥80 硬伤强制 ≤79）           │
└─────────────────────────────────────────────┘
  │
  ▼
最终分数 + L 等级 + 生产字段（title/seotitle/category/tags/...）
```

这条链要能**按类目高度自定义**：红线规则集、赛道划分、每赛道的维度 Schema、固定通用维度的加权降权表、封顶规则，都进类目合同并在入队时冻结。

## 3. 「调用A / 调用B / 维度」职责边界（要钉死的核心）

这是文档明确点名要理清的。我的建议边界如下——**每个位置填什么配置要唯一、不重叠**：

| 位置 | 职责（唯一） | 输入 | 输出 | 不允许做 |
|---|---|---|---|---|
| **调用A（预检/分类）** | 客观事实识别：红线信号、媒介类型、赛道分类、生产字段（title/seotitle/category/style/tags/cons/design/reason/image_defects/trait/image_quality/media_form）、初步参考 score | 图片 | `production_fields` + `classification` + `media_form` + 红线命中证据 | 不出维度分、不出最终 L 等级、不做加权 |
| **调用B（维度评审）** | 主观质量分档：只对「未被红线淘汰」的素材，按赛道对应维度 Schema 逐维打 grade+证据+缺陷 | 图片 + 冻结的维度 Schema | `dimensions{grade,evidence,defects,uncertainties}` + `special_checks` + confidence | 不出总分、不出最终 L 等级、不做红线判定、不做媒介降权（那是服务端确定性算的） |
| **维度（Schema/聚合）** | 服务端**确定性**逻辑：把 A 的红线/媒介、B 的 grade，按类目冻结的权重/基底分/降权表/封顶铁律，算出最终 score 和 L 等级 | A + B 的结构化输出 | 最终 score + L 等级 + cap_reasons + hard_reject | 不调用模型（纯函数、可回归、可复现） |

一句话记忆：
- **调用A = 看「这是什么、有没有硬伤」（事实+红线）**
- **调用B = 看「这做得好不好」（分维度质量）**
- **维度层 = 确定性地把上面两者算成分数和等级（不碰模型）**

文档里「调用A（输出字段）」「调用B（提示词）」正好印证：A 管字段产出，B 管维度评审提示词。红线和媒介降权这类**规则性**的东西必须落在服务端确定性层，不能塞进 B 的提示词里靠模型自觉——否则不可回归、不可复现、会漂。

## 4. 通用底座怎么设计（支持任意类目自定义）

复用 ADR-0028 的「类目模板事实源 + 入队冻结」思路，给类目合同扩三块：

### 4.1 红线规则集（新增，节点0）
```
redline_policy:
  version: "redline-v1"
  enabled: true
  hit_level: "L5"          # Owner 已确认：红线废图档
  hit_score_cap: 49
  rules:
    - key: screenshot        # 截图
      signal_source: production_fields.reason  # 复用A已有的 reason 枚举
      match: ["是截图"]
    - key: snapshot           # 随手拍
      match: ["是随手拍"]
    - key: large_text         # 大面积文字≥40%
      match: ["有大面积文字说明"]
      exemptions: ["专业海报", "轻量化效果图辅助文字"]
    - key: large_qrcode       # 大面积二维码≥50%
      match: ["有二维码"]
      exemptions: ["角落极小尺寸"]
```
关键点：红线信号**尽量复用调用A已经产出的 `reason` 枚举**（是截图/大面积文字/多拼图/二维码/随手拍/颠倒图），不新造一套模型输出。服务端确定性匹配，命中即淘汰。

### 4.2 赛道/子类目 → 维度 Schema 映射（复用现有 dimension_router，扩展）
现有 `material-family-routing` 已经在做 space/product/graphic/intent/common 的路由。灵感图的「一类/二类/三类」可映射为：一类→space、二类→product、三类→common/简易维度。**扩展点**：允许每个类目定义自己的赛道集合和「赛道→维度Schema+基底分+封顶」表，而不是全局硬编码五族。

### 4.3 固定通用维度（新增，跨赛道共享）
```
common_modifiers:
  media_type_penalty:        # 媒介类型固定降权
    baseline: "real_photo"   # 实拍为基准
    penalties: { real_photo: 0, render_3d: -5, ai_image: -15, other: 0 }
    source: production_fields.trait   # 复用A的 trait 字段
  high_score_veto:           # 80分以上一票压分
    threshold: 80
    cap_to: 79
    triggers: [...]          # 硬伤清单（可配）
```
这项是「固定加权降权项」，跨所有赛道生效，独立于赛道维度 Schema。

### 4.4 全部进「类目合同」+ 入队冻结
和 ADR-0028/0031 一致：草稿→配置→启用；任务入队冻结完整 `evaluation-category-profile-v3`（在 v2 基础上加 redline_policy + track_map + common_modifiers）；后续改配置只影响新任务，历史结果/黄金集/回归证据不漂移。

## 5. 前后端改动范围（初估，待细化）

### 后端
- 新增 `redline_policy.py`：确定性红线匹配（纯函数，可回归）。
- 扩展 `category_pipeline.py`：类目合同加红线/赛道映射/通用降权，冻结版本 v3。
- 扩展 `dimension_router.py`：赛道集合与「赛道→Schema」从类目合同读，不再全局硬编码五族。
- 扩展 `scoring.py`：把「基底分 + 维度扣分 + 媒介降权 + 红线淘汰 + 高分压分」收敛为一个显式、有序、可解释（cap_reasons/hard_reject）的确定性聚合器。
- worker：在评分前插入红线节点；命中则短路，不发起调用B。
- 迁移：新增 v3 profile 字段，回填旧类目等价合同 + `PRAGMA foreign_key_check`。
- 回归/二审：`baseline_regression.py` 增加 red-line 命中率、误淘汰、媒介降权分布等指标；二审包显示红线状态。

### 前端
- 类目配置页：红线规则编辑器（规则集 + 豁免）、赛道→维度Schema映射表、固定通用维度降权表编辑。
- 结果/纠偏页：显示红线命中（哪条规则）、hard_reject、媒介降权明细、压分原因；红线命中样本走「直接定级」展示，不显示维度分。
- 明确三个填写位「调用A提示词 / 调用B提示词 / 维度Schema」的界面分区和说明文案，按第3节边界给 placeholder 和校验。

### 不破坏约束（延续现有 ADR）
- 已入队任务合同不漂移；红线/维度全部冻结快照。
- 服务端规则不塞进模型提示词；红线和降权是确定性层。
- 不允许模型覆盖人工真值、不允许绕过二审发布。
- 仅提示词模式（enabled=false）与红线节点如何共存，需单独定义（红线可独立于维度评分存在）。

## 6. 需要老大拍板的决策点

1. **L 等级方向**：Owner 已确认按钉钉文档执行，L5=最差、L1=最优；红线命中直接 L5。— **最高优先**
2. 红线信号是否统一复用调用A的 `reason` 枚举？还是红线要独立的模型判定字段（更贵但更专注）？
3. 赛道分类（计分基底用的一类/二类/三类）和「一级分类标签」（建筑设计/景观设计/...17类）是**两套并存**（我理解是的：前者管分数、后者管标签），确认一下？
4. 灵感图这套要不要作为**第一个样板类目**跑通，再抽象成通用底座？还是先做通用底座框架再填灵感图？我建议**先用灵感图把链路跑通，同时把可配置项抽出来**，避免过度设计。
5. 这次是否需要新的评分合同（红线直出等级）通过独立回归门禁（ADR-0028 后果里提到「完全无维度的直出等级需要单独评分合同」）——红线直出正属于这一类。
