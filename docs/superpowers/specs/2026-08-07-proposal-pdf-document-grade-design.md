# Proposal PDF Document-Level Grading Design

**Date:** 2026-08-07
**Status:** Approved by Owner in the current task

## Goal

让 `proposal_text_pdf` 使用分页图片作为模型输入，但始终以原始 PDF 作为唯一评测对象：调用 A 的批次结果必须先合并为一份文档级预检，调用 B 的代表页只提供文档级评分证据，最终等级由服务端确定性引擎生成。

## Root Cause

当前分页合并器把每个批次当作整份 PDF 的完整结论。普通字段（例如项目名称、分类依据、概念摘要）在不同批次出现不同值时，合并器直接转人工复核；某批调用 A 连续两次非法时也立即停止剩余页扫描。因此“分页输入”被错误地当成“分页评分”，合法 PDF 无法进入调用 B 和引擎定级。

## Design

### A. Document-level aggregation

- 红线命中项按 `类型 + 说明 + 证据` 去重后取并集；任一真实红线命中，整份 PDF 淘汰并不调用 B。
- 普通标量字段按批次顺序采用首个非空值；不同值写入 `信息提取._聚合审计.字段冲突`，不阻断评分。这样项目名称等元数据可审计但不会把一份 PDF 拆成多个样本。
- 分类字段按各有效批次实际覆盖页数加权后做确定性多数票；平票或没有有效分类时人工复核。
- 内容完整性采用 `是 > 无法判断 > 否` 的保守并集；图像统计按批次求和。
- 预检状态仅由文档级红线、分类收敛、页覆盖和不可恢复批次决定；`通过` 时 `是否进入B=true`。

### B. Invalid-batch recovery

- 每个原始页批先执行现有两次校验。
- 两次失败后将该批确定性二分，递归到最小 1 页。默认 16 页原始批最多恢复 4 层（16→8→4→2→1）；恢复后的子批结果按同一聚合器合并。
- 仍有页无法恢复时保留失败批次审计并人工复核，不截断、伪造或改写模型分数。
- 只有全部页被成功扫描、或已被红线明确终止，才允许文档级 `通过`。

### C. Scoring and UI

- B 的输入包含完整文本层摘要、目录和确定性代表页；提示词明确“评分对象为整份源 PDF，页图仅为证据载体”。
- `proposal_text_pdf` 的 scoring JSON 继续走 `v3_authoritative`，`dimension_mode=none` 不再触发图片维度合同错误。
- 审核列表识别 PDF 文档级结果，展示等级/分数；人工复核展示“PDF 文档级复核”及聚合/恢复原因。
- 不提供逐页图片下载或导出接口。

## Data and Compatibility

- 新合同版本：`proposal-text-v2-document-aggregate-20260807`；A/B 提示词版本随合同冻结。
- 旧结果保留原 JSON，可按历史合同读取；新任务只接受 v2 合同。
- 不新增数据库表或迁移；聚合审计写入现有 `precheck_json` 与 `preprocess_json`。

## Verification Contract

- 单测覆盖：普通字段冲突不再人工复核、分类平票人工复核、红线并集、内容完整性合并、非法批递归恢复、不可恢复批 fail-closed。
- Worker 集成覆盖：32 页两批全扫描、A 异常恢复后仍进入 B、文档级 scoring 产出等级、PDF 审核列表状态不再显示维度合同异常。
- 后端全量测试、前端 TypeScript/Vite 构建、`git diff --check` 必须通过；生产环境零触碰。
