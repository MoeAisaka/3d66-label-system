# PDF 方案文本送审通道 Owner 冻结设计

**状态：** Accepted
**日期：** 2026-08-06
**适用类目：** `proposal_text_pdf`
**型材：** `text-proposal-additive-v1`

## 目标

在不改变灵感图类目任何合同、提示词或评分行为的前提下，把 PDF 方案文本改为“文本层优先、逐页图像补充”的确定性输入通道。禁止长图拼接；调用 A 分批覆盖全本，调用 B 只看引擎确定性选择的代表页。

## 冻结架构

1. 引擎使用 pypdf/PyMuPDF 读取总页数、目录和逐页原生文本。文本层是文本字段的第一信息源；仅无原生文本的扫描页/纯图页执行 OCR。
2. 调用 A 将每页渲染为独立图片，长边不超过 1024px，每 16 页一批，按页码顺序串行调用。任一批命中红线，立即停止后续批次。
3. 调用 A 合并时红线去重取并集；普通信息字段采用“首个非空值”并记录来源批次。后续批次出现不同非空值时转人工复核。图像统计是批次局部计数，按字段求和，避免多批必然冲突。
4. 调用 B 最多使用 16 个独立代表页，不拼成长图，不让模型自选页。引擎固定包含封面，再根据调用 A 的图像统计、PDF 目录和逐页文本关键词，在效果图、分析图、概念推导页之间确定性分配名额；不足时按跨文档均匀覆盖补齐。
5. B 页使用独立高保真渲染结果，不进行缩略图降采样。B 文本输入包含目录结构、确定性文本层摘要、A 合并结果和代表页页码。
6. 任一 PDF 解析、批次输出、跨批冲突或 B 输出持续失败均 fail-closed：不猜测、不截断改写模型输出，转人工复核并保存完整审计线索。
7. 预处理缓存按 PDF 内容哈希、通道 schema 和 batch/sample/分辨率参数寻址；原 PDF 字节永不修改。
8. 单份评审的 A/B 输入、输出和合计 token 必须从模型响应 usage 汇总进执行快照，并在 142 报告中列出实测值。若受“不得占用阶段 1c 豆包预算”阻断，必须显式列为未验收缺口，不能用估算冒充实测。

## 错误与验收

- 元数据总页数小于 15：模型调用数为 0，直接淘汰。
- 元数据不可读但可渲染：进入 A 批扫；A 仍不能判断时转人工复核。
- A 红线：停止后续 A 批次，B 调用数为 0。
- A 信息冲突：转人工复核，B 调用数为 0。
- 无红线且无冲突：B 恰好调用一次，图片数不超过 16。
- 执行快照能回答：A 批次数、已扫描页数、停止原因、代表页页码、A/B token。
