# 基准回归运行配置与五档等级证据恢复设计

状态：Proposed  
日期：2026-08-14  
关联：本设计补充并部分替代 `2026-08-14-baseline-regression-level-bucket-metrics-design.md` 的页面展示部分；三档聚合口径保持不变。

## 1. 背景与根因

基准回归运行配置抽屉当前把提示词、执行模式、A、B、V3 合同和启动按钮放在同一行。布局断点依据整个浏览器 viewport，而不是抽屉容器宽度；在桌面宽度达到断点后，约 680px 的抽屉被强制压成六列，合同摘要列收缩为单字宽，出现文字竖排和严重挤压。

基准回归等级证据在字段指标重构时从主结果区移除了原有 L1–L5 矩阵。后续新增三档聚合指标时只增加了摘要组件，没有恢复主结果区的五档分布矩阵和每个等级的准确率/召回率展示。后端 `BaselineLevelMetrics.confusion_matrix` 仍然稳定返回完整五档事实，因此不需要补造数据或改变指标口径。

## 2. 目标

1. 让运行配置在 1280px、1440px 和 1920px 等桌面宽度下可读、可操作，不再出现单字竖排或横向溢出。
2. 让同类目 V3 合同支持“当前现役”与“手动选择非现役候选”，并与提示词 A/B 的版本选择体验一致。
3. 选择非现役 V3 candidate 后自动匹配其合同绑定的 A/B；人工仍可调整，但不匹配时必须在启动前被明确阻止。
4. 恢复并保留 L1–L5 五档 5×5 分布矩阵，同时展示每档准确率（Precision）和召回率。
5. 保留已有精确等级准确率、相邻等级准确率、推荐档/常规档/过滤档聚合、字段证据、历史 run 和人工决策边界。

## 3. 非目标与边界

- 不新增数据库表、字段或迁移。
- 不改变 V3 候选创建、人工启用、退役、发布或回退门禁。
- 不把候选 revision 自动激活，不发布标签事实，不触发存量重跑、真实模型调用、自动组批或生产写入。
- 不改变移动端目标；验收只覆盖电脑桌面。
- 不重做字段证据抽屉、纠偏工作台或其他页面的通用信息架构。

## 4. 运行配置交互

`RunConfigDrawer` 使用宽版抽屉（目标宽度约 820px），内容按分区纵向排列：

### 4.1 提示词配置

- 取值方式继续支持当前发布版本、手动选择版本、单提示词。
- A/B 选择器最多两列排列。
- 显示版本号和状态，保留现有类目过滤和流水线范围校验。

### 4.2 V3 合同配置

- 取值方式支持当前现役版本、手动选择版本。
- 默认选择当前运行时投影对应的 active revision。
- 手动选择只允许同类目、状态为 `candidate` 且祖先链仍追溯到当前现役投影的 revision。
- `draft`、`retired` 和已脱离当前现役祖先链的 candidate 进入历史分组，只读展示并禁选。
- 版本条目展示 revision、合同显示名、状态和短哈希；选中后展示合同摘要。

### 4.3 A/B 与 V3 联动

- candidate 合同若包含 `prompt_bindings.call_a_version` 或 `call_b_version`，选择该 candidate 后自动切换到提示词手动模式并预选绑定版本。
- 人工可以调整 A/B；若与候选合同绑定不一致，启动按钮禁用，并给出缺失或不匹配的具体版本信息。
- 服务端仍是最终权威，继续校验类目、candidate 状态、祖先链、投影漂移和 A/B 绑定。

### 4.4 执行与提交

- 自由实验/标准评分合同独立成第三段。
- 启动按钮移入抽屉固定底栏，底栏同时展示即将冻结的 A、B、V3 摘要。
- active 模式请求不传 `candidate_revision_id`；candidate 模式准确传递所选 revision ID。
- 运行成功后历史记录显示启动时冻结的 V3 revision，不随之后的激活、退役或新候选变化。

## 5. 五档等级证据

主结果区在已有等级汇总和三档聚合之后恢复一个独立的“L1–L5 等级分布”区域：

- 矩阵行表示人工真值/期望等级，列表示模型预测等级。
- 固定展示 L1、L2、L3、L4、L5 的全部 25 个格子，零值也必须展示。
- 每一行末尾展示该等级召回率：`diagonal / row_total`。
- 最后一行展示每档准确率（Precision）：`diagonal / column_total`。
- 分母为零显示 `—`，不得把无样本误报为 0%。
- 对角线有命中时保留现有高亮语义，但状态不能只靠颜色表达。
- 现有精确等级准确率、相邻等级准确率和推荐档（L1/L2）、常规档（L3/L4）、过滤档（L5）精确率/召回率继续展示；三档只是附加聚合，不替代五档矩阵。

所有计算均基于当前 run 的 `metrics.confusion_matrix` 前端纯函数完成。后端现有五档矩阵和分母规则保持不变，历史轮次切换时整体随当前 run 更新。

## 6. 数据流与错误状态

1. 选定类目后读取提示词列表、V3 revision 列表和当前投影 revision。
2. revision 列表加载失败时禁止启动并提供重试，不静默回退 active。
3. candidate 在提交前失效、祖先链漂移或现役投影变化时，接受服务端 409，刷新版本列表，不自动替换为 active 运行。
4. candidate 缺少绑定的 A/B、绑定版本已归档或人工修改后不匹配时，前端明确阻止启动，后端继续返回结构化错误。
5. 历史 run 没有 V3 revision 元数据时显示“历史 run 未记录”，但不影响已有矩阵和指标。
6. 等级分母为零时显示 `—`；没有有效预测时矩阵仍展示完整空矩阵。

## 7. 实现边界

预期改动集中在：

- `frontend/src/components/workspace-page.tsx`：为抽屉提供不影响默认调用方的宽版能力；
- `frontend/src/features/baseline-regression/run-config-drawer.tsx`：保留抽屉语义并承载固定底栏；
- `frontend/src/pages/baseline-regression-page.tsx`：版本查询、A/B 联动、启动 payload 和矩阵接入；
- `frontend/src/features/baseline-regression/level-performance-summary.tsx`：增加五档矩阵与单档指标；
- `frontend/src/lib/api.ts`、`frontend/src/lib/types.ts`：补充 revision 列表/冻结摘要类型；
- 必要时仅在 `backend/app/main.py` 的 run selection 序列化中补充历史 V3 revision 展示字段；
- 相关前端合同脚本与后端基准回归测试。

不得修改全局抽屉的默认宽度、V3 激活 API、数据库迁移、真实执行器或发布脚本。

## 8. 测试与验收

### 8.1 确定性测试

- 先为运行配置布局、active/candidate payload、candidate-A/B 联动和不匹配禁用状态写失败合同，再实现。
- 为单档 Precision/Recall 纯函数覆盖：对角命中、跨档误判、空行、空列、全空矩阵。
- 合同断言确认主结果区存在 25 个矩阵格子、L1–L5 单档准确率/召回率、两项总体指标和三档聚合。
- 后端保留现有 candidate revision 祖先链、投影漂移、A/B 绑定和冻结快照测试；如序列化字段扩展则增加历史 run 展示回归。
- 运行后端全量、前端 TypeScript/lint、前端合同脚本和 Vite production build。

### 8.2 Edge 桌面验收

- 使用 Edge 的临时确定性数据，在 1280×720、1440×900、1920×1080 检查抽屉无横向挤压、无单字竖排、无控制台 error/warning。
- 选择 active 与 candidate 两种 V3，确认 A/B 联动、状态分组、禁用历史版本和启动摘要；不点击真实运行按钮。
- 切换至少两个历史 run，确认五档矩阵、单档指标和三档聚合随当前 run 刷新，25 格完整保留。

## 9. 回退与停止条件

- 本批不产生数据库迁移；实现以单一可回退提交交付，回退为 revert 该提交即可。
- 若发现必须扩大到发布门禁、权限、数据库迁移或测试服部署，立即停止并重新确认合同。
- 本阶段不推送、不合并、不部署；后续发布须以唯一 combined main 为准并重新取得精确授权。
