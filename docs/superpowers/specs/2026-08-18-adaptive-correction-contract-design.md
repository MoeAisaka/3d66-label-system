# 版本合同驱动的自适应纠偏面板设计

## 状态

已获 Owner 确认，待实现。日期：2026-08-18。

## 背景

当前纠偏页能够读取部分冻结维度和 v3 结果，但生产字段仍有前端固定列表，等级撮合器也只展示有限阈值。机制版本增加、删除或改变字段后，页面可能继续展示旧条目，导致新机制已经更新而运营无法纠偏对应节点。

目标不是让历史回归跟随现役机制变化，而是让每一轮新回归使用自己的完整机制合同生成纠偏面板。

## 已冻结目标与边界

- 存量基准回归、增量审核、候选回归共用一套合同驱动纠偏内核。
- 维度、生产字段、调用 A/B 节点和 v3 等级撮合节点均由版本合同描述。
- 回归创建时冻结提示词、字段合同、v3 合同、纠偏合同及其哈希；纠偏页只读取该快照。
- 不允许运营直接编辑全局规则代码或现役阈值；运营纠正样本上的规则判断，AI 生成候选机制并继续回归。
- 不改写历史评测、人工真值、模型原始响应、现役机制或标签事实发布轴。
- 本次不包含 NAS 存储迁移、真实模型批量调用、自动启用候选、存量重跑和测试服部署。

## 方案

### 1. 合同模型

新增不可变 `correction_contract` 描述，作为机制版本和运行快照的一部分。合同至少包含：

- `contract_version`、`contract_hash`、`category_key`；
- 节点稳定标识 `node_key`、所属层 `A/B/V3`、路径和排序；
- 中文名称、说明、数据类型、允许值/范围、是否必填和证据要求；
- 节点语义版本与兼容标识，用于跨版本继承；
- v3 节点类型：规则命中、阈值比较、封顶/降档、等级映射和最终等级；
- 结果重算所需的服务端规则引用，不允许前端提交可执行代码。

合同是表单元数据和服务端校验合同，不替代评分引擎的权威规则。缺少稳定标识、类型、中文说明、取值约束或 v3 重算引用的候选不能启用。

### 2. 运行冻结

创建增量或存量回归时，后端解析当前选中的机制版本，把提示词、维度/生产字段合同、v3 规则、纠偏合同和版本哈希写入运行快照。每个 `EvaluationResult` 继续保留其自身策略快照；后续现役版本变化不得影响旧运行。

候选回归必须冻结候选合同，且继续遵守当前候选 revision、提示词绑定和现役祖先链门禁。

### 3. 后端纠偏视图与提交

后端返回统一的 `correction_view`：

- 冻结合同身份和版本状态；
- 模型原值、当前计算值、人工值和历史来源；
- 可编辑类型、选项、范围和证据要求；
- 当前 v3 重算路径、命中规则、阈值判断、封顶/降档和最终等级；
- 按稳定节点匹配的上一轮人工结果与合同差异标记。

提交请求携带 `contract_hash`、`node_key`、人工值、理由、证据、审核修订号和幂等键。服务端必须按本轮冻结合同验证节点、类型、范围和审计身份，并基于冻结 v3 合同重算结果；哈希过期、合同外节点和非法值均 fail-closed。

节点纠偏仍采用追加历史，原始模型响应和旧人工轮次不可变。调用 A/B/V3 路由继续由结构化人工证据驱动，运营不直接改变全局机制。

### 4. 跨版本继承

- 稳定标识、类型和语义兼容：预填上一轮人工值、理由和证据，并显示来源轮次。
- 新增节点：显示“新增待确认”，不自动猜测人工值。
- 删除节点：新页面不展示，历史记录保留。
- 类型或语义变化：不继承，显示“不可继承/合同已变化”。
- 继承仅作为编辑初值，不改变本轮模型结果或人工真值，运营提交后才产生新轮次记录。

### 5. 前端动态面板

前端使用共享渲染器，按 `correction_view` 分组展示调用 A、调用 B 和等级撮合器。支持枚举、整数/小数、布尔、文本、列表及规则判断节点；复杂 v3 节点由后端给出可读步骤，不由浏览器解释规则代码。

页面顶部固定显示本轮提示词、v3 版本、合同哈希及“历史快照/当前现役”状态。候选启用成功后刷新类目、提示词和 v3 版本查询，但当前旧回归页仍保持自己的冻结合同。

### 6. 历史兼容与门禁

历史记录缺少完整纠偏合同时，只能从该记录自身归档字段生成兼容面板；不能读取现役配置补齐。若归档字段不足，则只读展示并逐项列出不可纠偏节点，不静默隐藏。

新候选启用前必须通过合同完整性门禁：所有模型可输出字段、纠偏节点和 v3 决策节点都有稳定标识与完整表单描述。该门禁失败时保留候选和证据，但禁止启用。

## 数据与接口影响

优先采用增量、可回退的数据库变更：在运行/评测快照或独立纠偏合同快照表中保存规范 JSON 与哈希，保留旧列和旧 API 兼容读取。具体表和迁移编号在实施计划中冻结，禁止删除或重写历史 JSON。

建议新增或扩展以下只读/写入边界：

- 运行创建：冻结并返回纠偏合同身份；
- 纠偏详情：返回 `correction_view`；
- 纠偏提交：接收带合同哈希的结构化节点证据；
- 候选启用：执行合同完整性门禁，并使前端版本查询失效。

所有 API 返回中文可读错误和稳定错误码；不得返回密钥、会话令牌或内部凭据。

## 验证设计

1. 构造连续两个机制版本，覆盖维度、生产字段和 v3 节点的新增、删除、类型变化、语义变化。
2. 验证旧运行仍显示旧合同，新运行新增条目漏显数为 0。
3. 验证存量、增量和候选回归共享渲染器及服务端校验。
4. 验证兼容继承、不可继承提示、保存/再次修改/上一条/下一条/刷新后的持久化。
5. 验证 v3 节点修改后的重算与正式评分引擎一致。
6. 验证过期哈希、合同外字段、描述缺失候选均被阻止。
7. 验证结构化证据正确路由到调用 A、调用 B 或 v3，且候选不会自动启用。
8. 后端专项、前端合同与正式构建、三链路集成测试、真实浏览器关键路径和 `git diff --check` 全部通过。

## 回退与停止

数据库只做增量迁移，代码以独立提交回退；旧纠偏读取路径保留至兼容验证完成。若出现破坏性迁移、评分重算不一致、无法解释字段语义、并行分支冲突或测试失败，立即停止，不推送、不合并、不部署。
