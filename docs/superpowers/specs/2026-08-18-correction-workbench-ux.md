# 纠偏工作台连续处理与修订持久化规格

## 目标

让运营在基准回归纠偏中连续处理素材：图片始终可见，提交后进入下一条待处理素材，人工结果可持久查看并以新修订继续修改，同时补齐 V3 等级撮合器节点纠偏入口。

## 冻结行为

1. 纠偏详情桌面端为左侧固定图片、右侧滚动编辑；移动端退化为上下布局。
2. 成功提交“确认、退回或维度纠偏”后，按当前页面顺序自动打开下一条未完成素材；同时保留手动“下一个”按钮。
3. 已完成素材不进入自动下一条候选；当前页无下一条时显示本页处理完成，并允许返回列表。
4. 提交成功后不再等待无关全局查询全部刷新；当前回归详情先刷新，其他看板后台刷新。
5. 人工结果持久保存在服务端。再次进入已完成素材时展示当前人工结论与历史记录。
6. 点击“再次修改”创建新的审核轮次，保留旧轮次，重新进入初审；禁止覆盖旧真值。
7. 新轮次沿用现有初审组人数、乐观锁、服务端权威重算、黄金集沉淀与审计规则。
8. 基准回归纠偏页只要存在冻结 `v3_context` 就展示 V3 节点纠偏工作台，不再错误依赖 `dimension_scoring_mode=rule_deduction`。
9. V3 节点纠偏继续复用现有 `correct-node` 接口，覆盖调用 A、红线、赛道、规则命中和最终等级；最终等级人工覆盖不改写权威分，事件追加留痕并进入 V3 优化路由。

## 非目标

- 不修改豆包模型、提示词、V3 现役合同或类目阈值。
- 不自动发布人工纠偏形成的候选机制。
- 不改变二审/仲裁规则和初审人数策略。
- 不调整测试服硬件或数据库类型；性能先修复已确认的前端阻塞与超量刷新。

## 并发边界

- 独立分支 `codex/correction-ux-next-persistence-20260818`。
- 不修改 3D/SU 会话当前未提交的 `frontend/src/lib/types.ts`、`frontend/src/lib/dimension-schema.ts`、`backend/app/v3_review_dimensions.py` 和维度合同测试脚本。
- `backend/app/main.py` 与 `backend/app/models.py` 若产生文件级重叠，只新增审核轮次相关小区块，合流前逐段核对 3D/SU 差异。

## 验收

- 后端：已完成记录可重开为下一审核轮次；旧轮次仍可查询；新轮次投票不混入旧轮次；并发旧修订返回 409。
- 前端：固定图片、手动下一条、成功后自动下一条、再次修改、历史结果展示、V3 节点入口均有合同测试。
- 性能：提交成功路径只等待当前基准回归详情刷新，其余查询后台失效，不再同步等待全局评测列表。
- 构建：后端专项测试、迁移测试、前端合同检查、类型检查和生产构建通过。
