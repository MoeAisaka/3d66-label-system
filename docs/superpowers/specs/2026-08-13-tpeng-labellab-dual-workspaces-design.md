# TPENG 标签实验台双链路与中台底座重构设计

> 状态：设计稿，待 Owner 审阅
> 日期：2026-08-13
> 产品：TPENG 标签实验台（LabelLab）

## 1. 目标

将 TPENG 标签实验台从“多个评测/配置页面的集合”收敛为一个可持续扩展的标签生产与治理底座：

- 增量素材可按类目进入清晰、串行、可恢复的评测链路；
- 存量已定性素材可进入独立的回归与重跑链路；
- 两条链路复用平台内核，不复制任务、纠偏、版本、发布和对账能力；
- 黄金数据集成为可管理、可锁定、可导出、可复用的质量资产；
- 类目差异通过受控 profile 插件表达，支持 3D、SU、Proposal PDF 等专用编辑视图；
- 正式标签事实能够投影到“一个统一大维表 + 数个职责明确的小表”，并支持版本对账与失败补偿；
- 为 90 天目标提供可举证的“标签生产 → 真实消费 → 效果度量 → 反馈迭代”基础，但本轮不直接连接真实业务数据库或搜索生产环境。

## 2. 已冻结约束

1. “标签体系重构”和“标签实验台”是同一产品，统一名称为 TPENG 标签实验台（LabelLab）。
2. 业务类目是平台上的场景扩展，只提供类目合同、字段、提示词、维度、规则、回归门槛和专用视图。
3. 机制发布轴与标签事实发布轴独立；启用机制不会自动发布标签事实、覆盖历史标签或自动触发存量重跑。
4. 下游只消费正式发布事实，不读取候选机制、实验结果、模型原始响应或人工处理过程。
5. `semantic.*`、`quality.*`、`governance.*` 及人工真值、证据、来源、版本、审核和发布状态必须可追溯。
6. 搜索索引、知识图谱、向量索引以及下游数据库表均是可重建消费投影，不是事实主库；Query×素材相关性、排序权重和图谱内部关系不写入素材事实。
7. 桌面端是唯一验收形态；不以移动端布局作为目标。主视觉保持荧光绿行动色。
8. 最终候选机制必须由人工明确启用或拒绝。

## 3. 产品信息架构

### 3.1 一级工作区

一级导航只保留当前操作主线需要的内容：

1. **增量评测**：处理新进入、未定性的素材。
2. **存量回归**：处理已定性素材、黄金集和存量重跑申请。
3. **运行中心**：观察队列、并发、失败、重试、耗时、成本和恢复状态。
4. **质量资产**：管理黄金数据集、真值版本、锁定状态和导出。
5. **治理与发布**：管理模型、类目机制、候选决策、正式标签发布和投影对账。

复杂内容下沉到二级承载：评测包编辑器、机制编辑器、运行配置抽屉、指标抽屉、历史抽屉、证据查看器和纠偏工作台。一级页面不平铺完整 JSON、原始模型响应、所有历史轮次或全部逐样本证据。

### 3.2 增量链路

```text
选择类目
 → 导入增量未定性素材（手动或接入合同模拟事件）
 → 编辑评测包
 → 选择评测机制
 → 启动评测
 → 人工审核纠偏
 → 启动自动 AI 迭代
 → 自动候选样本回归
 → 人工确认候选机制与回归结果
 → 启用机制
 → 申请/执行正式标签发布
 → 生成下游表投影
 → 接收 Badcase 回流
```

本轮实现可验证的本地接入合同和链路状态，不把真实外部上游接入写成已上线能力。

### 3.3 存量链路

```text
选择类目
 → 导入存量已定性素材或选择黄金集
 → 编辑素材包/基准集
 → 选择评测机制
 → 启动回归
 → 人工审核纠偏
 → 启动自动 AI 迭代
 → 自动候选样本回归
 → 人工确认候选机制与回归结果
 → 启用机制
 → 申请存量重跑
 → 人工验收后正式标签发布
 → 生成下游表投影
```

真实大规模存量 Worker、批量差异工作台和批量发布仍是后续单独冻结的能力，不在本轮隐藏实现。

## 4. 共享平台内核

两条链路通过同一组平台服务实现，任务使用 `workflow_kind=incremental|stock` 做页面和上下文隔离：

- **资产接入与路由**：幂等键、来源、资产身份、来源版本、类目解析和 profile 校验；
- **任务编排**：素材包、评测包、回归运行和检查点状态机；
- **调度与并发**：`validation`、`interactive`、`production_batch`、`canary`、`recovery` 队列，配额隔离、空闲借用、供应商限流、分级重试和失败熔断；
- **评测执行**：冻结模型、提示词、机制、规则和资产输入快照，结果与运行版本绑定；
- **人工纠偏**：人工真值、证据、原因码和追加式历史；
- **AI 迭代**：冻结纠偏样本，自动生成完整候选机制包，自动创建候选回归，等待最终人工决策；
- **质量与回归**：黄金集、挑战集、字段级指标、混淆矩阵、失败样本和版本比较；
- **发布与消费**：机制发布轴、标签事实发布轴、表投影、Outbox、检查点、重试、补偿和对账；
- **审计与权限**：模型/机制/资产/人工/发布/投影全链路审计；候选启用为系统管理员最终动作。

## 5. 类目 profile 插件

平台注册表负责 profile 的注册、路由、校验、版本快照、权限和安全降级。profile 只提供：

- 输入输出合同；
- 模型与提示词绑定；
- 维度、证据和确定性规则；
- 评测/回归门槛；
- 专用编辑器和展示字段。

标准图像、Proposal PDF、3D、SU 保持独立合同。未知 profile 只允许只读摘要和 JSON 诊断，禁止执行任意前后端代码或写入。

## 6. 黄金数据集

质量资产工作区统一管理普通样本集、黄金集和挑战集：

- 人工真值包括标签字段、质量字段、治理字段、证据、原因码和修订历史；
- 锁定后形成不可变版本，评测包和回归运行只引用该版本；
- 支持按类目、字段、来源、版本和状态筛选；
- 支持 CSV、JSON 和带版本/哈希/字段说明的 Manifest 导出；
- 导出内容只包含已授权的正式真值和必要来源信息，不包含密钥、候选机制或内部模型凭据；
- 任何真值修订都生成新版本，不覆盖旧版本。

## 7. 正式事实与下游数据库表投影

### 7.1 事实与投影分层

Canonical 事实按 `semantic.*`、`quality.*`、`governance.*` 分域管理。下游采用数据库表投影，不把下游表反向当作事实源。

### 7.2 目标表形态

平台默认支持以下消费布局：

1. **统一大维表**：按稳定 `asset_id/content_key` 维护当前正式消费所需的宽字段集合，承载大多数下游查询和批量读取。它是正式发布事实的主要消费投影，但不拥有事实主权。
2. **数个小表**：按职责或消费场景拆分，例如搜索标签、质量/过滤、治理/来源、变更事件或专用类目字段。小表不能复制一套独立标签生产逻辑，只引用同一正式发布版本和 Canonical 来源。

### 7.3 表投影合同

每个目标表登记一份版本化 `ProjectionContract`：

- 目标系统、数据库、表名和环境；
- 主键、关联键和唯一性约束；
- 字段映射、字段版本和兼容策略；
- 输入资产版本、机制版本、模型版本、标签发布版本；
- 全量快照或增量 Outbox 模式；
- 幂等键、游标/检查点、重试、死信和补偿；
- 行数、缺失、延迟、哈希和版本对账；
- 回退到上一正式发布版本的方式；
- Owner、权限、变更审批和退出日期。

本轮实现 Registry、Manifest、本地模拟适配器和对账验证；不连接或写入公司真实业务数据库。

## 8. 质量指标与试用期目标映射

### 8.1 标签质量

黄金集回归至少输出：

- 字段级准确率、召回率；
- 关键字段宏平均、微平均；
- 混淆矩阵；
- 漏标、误标、冲突和低置信样本清单；
- 模型、提示词、机制、资产和真值版本对账。

任何候选机制不得只凭总体分数通过；关键字段退化、黄金集失败或高风险错误增加时，应阻止启用。

### 8.2 90 天结果映射

本设计服务于以下结果证据：

```text
标签生产
 → 正式发布事实
 → 统一大维表/小表投影
 → 首个业务消费场景（优先 3D 搜索）
 → 消费效果度量
 → Badcase 回流
 → 机制迭代与回归
```

实验台本身、模型准确率或表数量不能单独作为试用期成功标准；必须能证明至少一个真实消费切片的联调、版本切换、效果对照和回流闭环。真实消费接入不在本轮实施授权内。

## 9. 错误处理与回退

- 接入事件重复：按幂等键返回已有任务，不重复组包；冲突载荷进入人工处理队列；
- profile 缺失或版本不兼容：fail-closed，不启动评测；
- 模型调用瞬时失败：按错误类型退避重试，超过上限进入 recovery；
- 业务不确定：进入人工纠偏，不当作技术失败重试；
- 候选回归失败：保留候选和证据，禁止启用；
- 现役机制或正式表投影漂移：阻止启用/发布，要求重新回归或补偿；
- 表投影部分失败：不回写 Canonical 事实，记录检查点和差异，按合同补偿；
- 任何正式事实发布回退都使用追加式发布记录，不覆盖历史审计。

立即停止条件：发现候选机制自动进入正式环境、下游读取候选/人工过程、事实主库被投影反向覆盖、真实数据库被未授权写入，或无法证明版本/对账关系。

## 10. 本轮范围与非目标

### 包含

- 增量和存量两个一级工作台及串行步骤指引；
- 共享任务/调度/纠偏/回归状态和页面承载；
- 黄金集管理、锁定、版本和导出；
- profile 注册与安全降级；
- 多表投影 Registry、Manifest、本地模拟适配器和对账合同；
- 召回率、准确率和版本对账展示；
- 与现有双发布轴、权限、审计和桌面端约束对齐的文档与测试。

### 不包含

- 真实上游系统接入；
- 真实搜索、推荐或业务数据库写入；
- 大规模存量重跑 Worker、批量差异工作台和自动批量发布；
- Canonical 资产事实全面迁移；
- Embedding 生命周期、通用投影 Registry 的生产级多实例高可用；
- 自动采纳候选或自动发布标签事实；
- 移动端适配。

## 11. 验收标准

1. 增量与存量页面入口、步骤、状态和上下文明确隔离；必需前置未完成时不能启动后续动作。
2. 同一任务内能证明队列、并发配额、重试、检查点和恢复行为。
3. 本地模拟接入事件能够按类目自动组包并进入增量队列，重复事件不重复处理。
4. 黄金集能创建、维护、锁定、复用和导出；锁定版本不可静默改变。
5. 纠偏后能自动生成候选机制、候选回归和人工决策；候选不会自动启用。
6. 回归结果能按字段输出准确率、召回率、混淆矩阵和失败样本。
7. 正式发布能够驱动统一大维表和小表模拟投影，并完成版本、行数、缺失和哈希对账。
8. 现有双发布轴、权限、审计、Canonical 事实边界和荧光绿桌面视觉不回退。
9. 后端专项/全量测试、前端 TypeScript/Vite 构建、Edge 桌面主流程和 `git diff --check` 全部通过。

## 12. 后续阶段输入

真实生产阶段需由 Owner 另行冻结：

- 统一大维表和小表的真实库表清单、Owner、写入权限和单写者；
- 生产数据库连接方式、SLO/RTO/RPO、快照、金丝雀和回退；
- 3D 搜索首个消费切片的字段需求合同、查询/素材评测集、实验流量和效果指标；
- Canonical 资产版本、投影 Registry、Embedding 生命周期和真实存量重跑 Worker。
