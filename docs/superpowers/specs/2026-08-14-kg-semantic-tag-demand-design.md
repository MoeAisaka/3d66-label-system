> 关联：ADR-0042、ADR-0043、ADR-0044、ADR-0045，以及 `tpeng-platform-capability-map-and-gaps-20260811.md`

## 1. 目标

将知识图谱团队提出的 `space`、`object`、`style`、`material` 等字段提升为 TPENG 标签实验台的**平台级通用语义标签核心字段**，而不是 3D/SU 专属字段。

标签实验台负责统一生产、清洗、标准化、人工纠偏、版本发布和正式事实投影；知识图谱消费正式事实并构建实体、关系、路径和图谱投影。

首个验证切片仍选择国内 3D/SU 的整体与单体素材，但 Schema、字段合同和数据模型从第一天按全平台复用设计。

## 2. 不可破坏边界

- 原始模型输出是证据，不是知识图谱最终实体值，也不是 Canonical 事实。
- `semantic.*`、`quality.*`、`governance.*` 是标签中台 Canonical 事实命名空间。
- 搜索索引、知识图谱、向量索引和下游数据库表均是可重建消费投影，不能反向覆盖 Canonical。
- 知识图谱内部实体关系、路径和图结构 Embedding 由知识图谱负责，不写入素材语义事实。
- Query×素材相关性、召回融合、排序权重和在线实验参数属于下游策略，不进入素材标签事实。
- 国内/海外、整体/单体是同一平台合同的执行变体，不复制四套平台能力。
- 类目只通过适用性和扩展字段表达差异，不复制模型管理、纠偏、版本、发布和投影能力。
- 不因本设计直接接入真实上游、真实业务数据库、生产模型或生产发布。

## 3. 统一数据结构

### 3.1 资产身份

平台统一使用 `asset_id` / `content_key` 作为 Canonical 业务身份，并通过不可变 `asset_version_id` 追踪具体素材版本。

知识图谱需求中的 `ll_id`、`res_id` 只能作为下游表字段别名或来源系统字段，不能形成两套事实主键。

### 3.2 执行变体

四个知识图谱批次由一个合同加参数表达：

```text
site_scope: domestic | overseas
asset_scope: whole | single | other | unknown
locale: zh | en
category_key: 类目键
prompt_variant: whole | single
prompt_version: 冻结 Prompt 版本
model_version: 冻结模型版本
```

`is_single` 是面向兼容投影的派生字段：`whole=0`、`single=1`；Canonical 使用更通用的 `asset_scope`，避免把所有类目强行约束为二元单体/整体。

### 3.3 平台级语义核心字段

| 字段 | Canonical 类型 | 适用性 | 生产路径 | 投影规则 |
|---|---|---|---|---|
| `space` | 结构化实体值，支持主值与层级 | 按类目声明，可单值或多值 | 模型/规则/人工 | 知识图谱实体；下游可投影末级名称 |
| `object` | 实体数组，含 `entity_id`、名称、权重、rank | 多数视觉/模型类目 | 模型→标准化→人工 | 表投影可兼容 `value_weight` 字符串，但 Canonical 保持结构化 |
| `style` | 实体数组，含主次 rank | 视觉、案例、模型等类目 | 模型/词表/人工 | 中文/英文名称由实体映射生成 |
| `material` | 实体数组，含占比/权重 | 有材质语义的类目 | 模型/规则/人工 | 不允许只保留未映射原文 |
| `structural_features` | 特征实体数组 | 模型、空间、结构类目 | 模型/规则/人工 | 记录适用性和证据 |
| `architectural_element` | 构件实体数组 | 空间、建筑、模型类目 | 模型/规则/人工 | 由类目适用性决定是否输出 |
| `soft_decoration` | 实体数组 | 空间、案例、模型类目 | 模型/规则/人工 | 与 `object` 保持字段语义分离 |
| `hard_decoration` | 实体数组 | 空间、案例、模型类目 | 模型/规则/人工 | 与结构特征、材质分别建模 |
| `color` | 颜色实体或标准值数组 | 视觉类目 | 模型/标准色词表/人工 | 统一色系词表版本 |
| `title` | 本地化文本，带 locale | 非所有类目必需 | 模型/规则/人工 | 海外表可要求；国内不强制 |

每个 Canonical 字段值至少携带：

```text
value / entity_id / locale / rank / weight
source / evidence_ref / model_version / prompt_version
normalization_version / mapping_version / review_status
```

### 3.4 适用性和空值

字段在每个类目 profile 中声明为：

```text
required        必须产生
optional        可产生，缺失不阻塞
not_applicable  业务上不适用
not_detected    适用但当前未识别
needs_review    需要人工判断
```

Canonical 不用空字符串表达所有情况。下游兼容表可以按合同映射为空字符串，但必须保留 `null_semantics` 和原因证据。

## 4. 统一生产链路

```text
字段需求合同
→ 素材/版本接入
→ 类目适用性和执行变体路由
→ 模型/规则识别
→ 原始结果证据冻结
→ 字段解析与清洗
→ 中英文标准值映射
→ 标准实体映射
→ 去重与冲突检测
→ 人工纠偏与质量验收
→ Canonical 事实发布
→ 国内/海外表投影
→ 知识图谱消费投影
→ Badcase 回流
```

知识图谱不能跳过标准化和实体映射直接读取模型结果；两张交付表也不能成为标签事实主库。

## 5. 类目扩展方式

平台提供通用核心字段、版本、证据、审核、发布和投影能力；类目 profile 只增加：

- 适用性矩阵；
- 类目专属字段命名空间，例如 `category.model_3d_su.*`；
- 输入预处理合同；
- Prompt、模型和规则绑定；
- 类目专用人工编辑视图；
- 字段级质量门槛。

当前 `model_3d_su` 的美感等级、三赛道、五维分数属于 `quality.*` / 类目扩展事实，不替代平台语义标签核心字段。

## 6. 质量与发布门槛

知识图谱语义标签不能只使用 L1–L5 美感指标，必须增加字段级质量证据：

- 字段级 Precision / Recall；
- 标准实体映射覆盖率；
- 未映射值率；
- 重复率与冲突率；
- `not_applicable` / `not_detected` 语义准确率；
- 人工纠偏率和人工审核覆盖率；
- 中文/英文映射一致性；
- 资产版本、模型版本、Prompt 版本和投影版本对账率。

候选机制必须经历候选回归、`EvaluationPackage` manifest 绑定和人工批准，才能切换机制发布轴；正式标签事实发布轴仍需独立人工发布，不因机制启用自动覆盖存量。

## 7. 首个验证切片

第一阶段只实现一条纵向闭环：

```text
国内 3D/SU
→ 整体/单体执行变体
→ 通用语义核心字段识别
→ 清洗和实体映射
→ 黄金集与字段级回归
→ 人工纠偏
→ Canonical 事实发布
→ 国内素材识别标签表 dry-run 投影
→ 知识图谱消费验证
```

海外批次复用同一 Schema 和流水线，待模型选择、成本、语言质量和下游验收口径签认后再启用。

## 8. 实施前必须签认的输入

以下内容必须由知识图谱、搜索/消费方和标签 Owner 共同签认，未签认前只允许继续设计和本地模拟：

1. `space/style/object/material/color` 的标准词表、层级和实体 Owner；
2. `0.7/0.5/0.3` 的业务含义、排序和最多值数量；
3. `asset_id`、素材版本和一行一素材的粒度合同；
4. 国内/海外的来源判定规则和语言切换规则；
5. 各类目字段适用性矩阵与空值语义；
6. 标题字段的权威性、生成方式和海外消费要求；
7. 未映射实体、冲突标签和低置信结果的人工门槛；
8. 更新、删除、迟到事件、重跑、撤回和回退规则；
9. 两张下游表的字段映射、SLA、对账和最小写入权限；
10. 首个知识图谱消费切片的效果指标和 Badcase 回流入口。

## 9. 本设计的验收与停止条件

验收必须证明：四个执行变体共用同一字段合同；原始结果、标准实体和 Canonical 事实可追溯；两张表只是可重建投影；候选、实验结果和人工过程不进入下游正式消费；版本、行数、缺失、哈希和实体映射能够对账。

出现未授权真实数据库写入、候选自动启用、标签事实自动发布、投影反向覆盖 Canonical、或无法证明版本对账关系时，立即停止并回退到最近正式发布事实。
