## 暴露的问题（都是「调用A/B 判定」层面，非引擎缺陷）
1. **中差档偏高散乱**（出现 L1 85 分）：因为"中差"是人工业务判断（同质化/无引流价值），而 OpenClaw 代跑的维度 grade 打太高。真实 doubao 调用B + 产品校准的 rubric 会更严。**说明维度 rubric 的严格度需产品用真实模型校准**。
2. **中差/中等各有 1 张被红线淘汰**：代跑把"大面积文字/截图"红线判为命中 → 直接 L5。红线判定的松紧取决于调用A prompt，需真实模型验证。
3. **好/中等/中差分数带重叠**：区分度不足。根因同 1——维度 grade 由代跑给出，非产品最终 rubric。

## 结论
- **v3 确定性引擎（分数计算规则）验证通过**：红线淘汰、赛道基底、维度扣分、媒介降权、80压分、level 映射全部按产品规格正确执行，好/过滤/极差三档判定准确、单调性正确。
- **需产品下一步**：用真实 doubao 模型 + 校准后的调用A/B prompt 跑全量，校准维度 grade 严格度和红线松紧，让"中等/中差"的区分度达到业务预期。引擎不需要改，改的是 prompt rubric 的严格度（可在前端 v3 配置页调维度/红线，无需改代码）。
